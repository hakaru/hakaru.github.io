App Store でダウンロード →

PeerClock Metronomeの詳しいマニュアルを読む

対象バージョン・端末・使い方の範囲

PeerClock Metronomeは、規則的なクリック音と指揮の動きを表示するメトロノームです。1台で個人練習に使うほか、同じローカルWi-Fiにつないだ複数の端末でタイミングと再生操作を共有できます。

本書は、PeerClock 0.4.2を使うPeerClock Metronome 1.1.0（build 13）を対象にしています。公開版は2026年11月15日に確認しました。必要なOSはiPhoneではiOS 17以降、iPadではiPadOS 17以降です。App Storeの掲載情報にはApple Silicon MacとApple Visionの互換性もありますが、本書のタッチ操作はiPhoneとiPadを対象とし、他の環境での動作試験を意味しません。

PeerClock Metronomeの詳しいマニュアルを読む

最初の練習を始める

  1. アプリを開き、端末の音量を聞きやすい大きさにします。他の端末と同期する場合は、ローカルネットワークへのアクセスを許可します。
  2. 一定テンポで練習する場合は、自動加速を開き、テンポを自動で上げるをオフにして完了を押します。
  3. 大きなBPMの数字を上へドラッグすると速く、下へドラッグすると遅くなります。その下の列から4/4を選びます。
  4. 丸い三角ボタンを押します。再生中は四角に変わります。クリック音と動く点を目安に演奏します。
  5. 四角ボタンを押すと停止します。接続中の端末がある場合は、その端末にも停止が送られます。

初めて複数台で使うときは、全員が接続して同期表示を確認してから、操作する人を1人決めて開始してください。一定テンポの再生は共有の拍グリッドに沿って始まるため、最初に聞こえる音が必ずカウントインや第1拍になるわけではありません。強い小節頭の音を確認してから演奏に入ります。

複数の端末を接続する

  1. すべての端末に対応版を入れ、同じローカルWi-Fiにつなぎます。
  2. 各端末でPeerClock Metronomeを開き、ローカルネットワークを許可します。準備中は全員が停止しておきます。
  3. 端末数とSynced表示を待ちます。数字は見つかった他の端末の数で、名前付きの参加者一覧ではありません。
  4. 操作する端末でテンポ、拍子、自動加速を決め、再生を押します。
  5. 全端末が意図したパターンを再生していることを確認してから練習します。

Bonjourを使って自動で検出します。Host、Join、参加コード、IP入力欄、部屋選択はありません。時計の基準となる端末は内部で自動選出されるため、演奏者がマスターを指定する必要はありません。

再生開始後に加わった端末には、その時点の再生状態と設定がすぐ届くとは限りません。確実に参加させるには、一度全員を停止し、同期を待って、使う設定を確認し、操作担当の端末から再開してください。再接続したときも全体の確認が必要です。

同期表示の意味

  • Standalone：現在カウントされている接続端末がありません。単体での練習はできます。
  • Searching…：端末は見つかっていますが、現在は時計が同期済みの表示になっていません。
  • Synced：時計ライブラリが同期済みの状態を返しています。

横の±x.xmsの数字には注意が必要です。この版では、報告されたネットワーク往復遅延の半分を表示しています。実際に聞こえるクリック同士の差、補正後の時計のずれを測った値、誤差の保証範囲ではありません。

自動選出された基準端末は、基準として往復遅延がゼロと扱われるため±0.0msを表示することがあります。すべてのスピーカーが完全に一致している証拠にはなりません。表示と端末数で接続状態を確認した後、実際の出力を聞いてください。参加・退出・再接続時の移行中は、状態が落ち着くまで待って全員を再開する必要が生じる場合があります。

広告・権限・プライバシー

確認した公開版は広告付きの無料アプリです。購入画面、サブスクリプション、購入を復元する操作、有料の広告解除はありません。広告が準備できていれば、その端末で開始した停止操作3回ごとに全画面広告が表示される場合があります。他端末から受け取った停止は回数に加算されません。表示の有無は配信状況によります。

データを扱う主体と目的

開発者のHakaru Hiroseは、広告配信、利用状況の分析、安定性の診断にGoogleのサービスを利用しています。Google AdMobは、広告の配信と効果測定のため、端末識別子、広告への反応、IPアドレス、診断情報を扱う場合があります。Firebase Analyticsは利用イベントやアプリ・端末の情報を扱い、アプリはトラッキング許可の状態、広告と同意処理のエラーも記録します。Firebase Crashlyticsは不具合調査のため、クラッシュ報告と関連するインストール・端末情報を扱います。これらは外部サーバーに接続することがあります。時計同期がローカルで動くことは、アプリ全体がインターネットを使わないことを意味しません。

権限と選択肢

ローカルネットワーク権限は近くの端末を検出して通信するためのものです。App Tracking Transparency（ATT）の要求は、トラッキングと広告識別子（IDFA）へのアクセスに関するものです。拒否してもメトロノームを使えます。設定 → プライバシーとセキュリティ → トラッキングで変更できますが、拒否はすべての広告や診断処理を無効にするスイッチではありません。詳しくはAppleのトラッキング設定の説明を参照してください。

アプリはGoogle User Messaging Platform（UMP）で同意情報を要求し、必要な場合に同意フォームを表示するよう依頼します。表示される選択肢は、サービスの地域・アカウント設定に依存します。フォームが出た場合は、その選択肢に回答してください。1.1.0には、フォームを再表示する独立したプライバシー設定画面や、分析・クラッシュ報告を切り替えるスイッチはありません。操作できない選択肢についてはサポートへお問い合わせください。UMPの資料はサービスの仕組みを説明していますが、推奨される設定のすべてをこのアプリから操作できるわけではありません。

位置情報・音声・保存設定

アプリはGPS・位置情報の権限を要求せず、マイク音声も録音しません。ただし、広告サービスがIPアドレスからおおまかな地域を推定する場合はあります。自動加速設定は端末に保存し、同期ではローカル端末間で時計と操作情報を交換します。録音を交換する仕組みではありません。メールで問い合わせる場合、内容とメールアドレスは対応する受信者に伝わります。

Google Mobile Adsのデータ開示、Firebaseのプライバシー情報、App Storeの開示も参照してください。本書では、このアプリ固有の保存期間を定めたり、アンインストールによるデータ削除を約束したりしていません。プライバシー、保存期間、削除に関する問い合わせ先はhirose@hakaru.netです。
