À lire avant de commencer : version et usage

ChatArchive est une application Mac qui permet de conserver une copie lisible des conversations LINE. Elle importe l’historique disponible dans sa propre base locale, affiche les conversations et recherche dans le texte des messages. Elle ne restaure pas les conversations dans LINE, ne transfère pas de compte LINE, n’envoie pas de messages et ne récupère pas de contenu absent de la source.

Ce manuel a été vérifié le 15 novembre 2026. Le téléchargement de la version vérifiée est 1.0.0 (build 1), pour macOS 14.0 ou version ultérieure. Les métadonnées de l’image disque et le code source correspondant ont été examinés. La fiche Gumroad actuelle n’indique pas la version du logiciel livré ; il n’est donc pas établi que son téléchargement soit identique à cette version.

Le code distinct de 2.0.0 (build 2) ajoute des fonctions décrites ci-dessous uniquement sous la mention « Si votre application possède l’interface de 2.0 ». Un numéro de version en développement ne prouve pas que ces fonctions sont fournies à l’achat. Vérifiez la version installée avec Lire les informations dans le Finder et suivez les commandes réellement présentes.

L’interface de l’application comprend l’anglais, le japonais, le chinois traditionnel et le thaï. Les langues de ce manuel sont indépendantes. Les références au code décrivent l’examen d’un dépôt privé par le développeur ; elles ne constituent pas des liens publics de téléchargement du code.

Installer et choisir la source

  1. Obtenez ChatArchive par le canal officiel d’achat ou de téléchargement. Si vous recevez un DMG, ouvrez-le et copiez ChatArchive dans Applications avant de lancer l’application.
  2. Prévoyez assez d’espace libre sur le Mac pour la base importée, l’extraction temporaire et les exports. Une quantité fixe de stockage ne peut pas convenir à tous les historiques.
  3. Choisissez la base locale de LINE pour Mac ou une sauvegarde iCloud compatible de LINE pour iPhone. Elles peuvent contenir des périodes et des nombres de messages différents.
  4. Avant de remplacer une bibliothèque ChatArchive existante, consultez Sauvegarder et supprimer les données.

Pour importer depuis le Mac, installez LINE pour Mac, connectez-vous dans LINE et laissez-le ouvert. Pour importer depuis iCloud, la sauvegarde concernée doit être accessible par le compte iCloud Drive du Mac. ChatArchive ne fournit pas son propre formulaire de connexion à LINE ou au compte Apple.

L’application examinée est réservée à macOS. Elle ne lit pas les sauvegardes Android/Google Drive, les sauvegardes ordinaires d’iPhone créées dans le Finder ni n’importe quel fichier ZIP. La compatibilité avec tous les futurs formats de base ou de sauvegarde LINE n’est pas garantie.

Importer depuis LINE pour Mac dans 1.0.0

  1. Ouvrez LINE pour Mac et terminez la connexion. Vérifiez que le compte souhaité est actif, puis laissez LINE ouvert.
  2. Si nécessaire, autorisez ChatArchive dans Réglages Système de macOS → Confidentialité et sécurité → Outils de développement. Cette autorisation concerne l’accès au processus LINE en cours d’exécution.
  3. Dans ChatArchive, choisissez Import from LINE, puis Import from LINE for Mac.
  4. Attendez la fin de la détection, de la récupération de la clé, de la lecture de la base et de l’importation. Évitez de changer de compte ou de quitter LINE pendant l’opération.
  5. Vérifiez les nombres affichés à la fin, fermez la fenêtre et examinez plusieurs conversations et dates.

L’application lit la base locale chiffrée de LINE à l’aide d’une clé obtenue dans le processus actif. La base source est ouverte en lecture seule. Elle ne demande pas aux serveurs LINE l’intégralité des conversations passées. En présence de plusieurs bases candidates, la détection automatique donne la priorité à une base plus volumineuse ; il n’y a pas de sélecteur de compte ordinaire ici.

L’accès complet au disque ne remplace pas l’autorisation des Outils de développement. Si l’accès ou le déchiffrement échoue malgré l’autorisation indiquée, contactez l’assistance plutôt que de désactiver les protections du système. Dans l’interface de 2.0, l’importation Mac est masquée comme fonction de développement. Utilisez alors le parcours iCloud normal.

Importer une sauvegarde iCloud de LINE pour iPhone

Ce parcours est disponible dans l’interface examinée de 1.0.0 et constitue le parcours normal dans 2.0. Il lit le fichier archive.zip propre à LINE, pas une sauvegarde iCloud de l’appareil entier.

  1. Vérifiez que LINE sur l’iPhone possède une sauvegarde standard terminée et appropriée. Suivez les instructions officielles de sauvegarde de LINE pour l’interface actuelle du téléphone.
  2. Sur le Mac, utilisez le compte Apple qui peut accéder à cette sauvegarde et activez iCloud Drive. Laissez le temps nécessaire et une connexion Internet pour que le fichier devienne disponible.
  3. Choisissez Import from LINE → Import from iCloud Backup.
  4. Attendez le téléchargement, l’extraction et l’importation. Vérifiez les nombres, noms et dates. Les interfaces ultérieures affichent aussi Imported from.

La détection cherche sous ~/Library/Mobile Documents/iCloud~com~linecorp~line/Data-*/Backup/archive.zip. Elle utilise la première sauvegarde correspondante trouvée, sans écran de sélection par date ou compte ; elle ne garantit pas de choisir la plus récente. LINE pour Mac n’a pas besoin d’être ouvert pour ce parcours, et le lecteur iCloud n’utilise pas l’autorisation des Outils de développement.

Ce que contient l’historique importé

L’archive reflète les enregistrements présents dans la source choisie au moment de l’importation. Une importation réussie ne prouve pas que toutes les conversations échangées par le compte depuis sa création sont incluses. Les messages supprimés auparavant, l’historique ancien indisponible et les médias absents de la source ne peuvent pas être reconstitués.

Le lecteur iCloud traite les discussions individuelles, à plusieurs, les groupes, les comptes officiels et les enregistrements Keep Memo lorsque les tables attendues sont présentes. En l’absence de coordonnées, les noms peuvent être remplacés par des identifiants ou libellés génériques. Les types de messages inconnus peuvent apparaître sous forme de numéro de type.

Les copies Mac et iCloud sont des sources indépendantes. Le téléphone peut afficher un historique que le Mac n’a jamais stocké. Importer l’autre source remplace la bibliothèque ChatArchive actuelle ; les contenus ne sont pas fusionnés.

Conservez séparément la sauvegarde source si l’exhaustivité est importante. L’application lit certains champs, pas toutes les tables ni toutes les métadonnées LINE. En particulier, l’extraction des réactions dans 2.0 n’intègre pas les fichiers journaux SQLite de la sauvegarde ; l’exhaustivité des réactions n’est donc pas assurée.

Actualiser l’historique : remplacer, sans accumuler

Chaque importation Mac/iCloud remplace toute la bibliothèque de contacts, discussions et messages de ChatArchive. Cela concerne les deux versions examinées. Conservez une copie séparée avant d’importer une source plus récente, plus ancienne ou différente. Il n’existe ni mode de fusion, ni téléchargement incrémentiel, ni synchronisation automatique programmée.

  1. Sauvegardez la bibliothèque locale actuelle et créez les copies de lecture nécessaires.
  2. Vérifiez la source souhaitée et la période de sa sauvegarde.
  3. Relancez la même procédure d’importation.
  4. Comparez les dates les plus ancienne et récente, les conversations importantes et les nombres finaux à vos attentes.

L’importation s’exécute dans une seule transaction de base de données : une erreur de base pendant cette transaction annule ses modifications. Cette protection est utile, mais ne remplace pas votre sauvegarde.

Réimporter une source n’ajoute pas volontairement une seconde copie de chaque message existant. La bibliothèque est reconstruite depuis la source ; des doublons déjà présents dans celle-ci peuvent encore apparaître. Une source plus petite peut réduire la bibliothèque et supprimer un historique auparavant visible.

Lire les conversations et les messages anciens

La barre latérale gauche contient les commandes d’importation, d’exportation et de licence. La colonne centrale présente les discussions selon la date de leur dernier message. Sélectionnez une discussion pour la lire à droite. Le champ de recherche de la liste filtre les noms des discussions ; il ne cherche pas dans le corps des messages.

Une conversation charge initialement ses 200 messages les plus récents. Utilisez Load older messages en haut pour charger les pages précédentes, jusqu’à 200 messages à la fois. Voir uniquement une période récente ne prouve donc pas que les anciens messages importés sont absents.

Les messages sont regroupés par date et distinguent vos propres messages de ceux des autres. Le texte peut être sélectionné et copié. Dans l’interface de 2.0, les liens détectés peuvent ouvrir le navigateur système ou l’application associée. Ouvrir un lien est une action distincte de la lecture de l’archive locale.

Si une date paraît incohérente, conservez la source et signalez la version et le parcours d’importation. Le code postérieur à 1.0.0 modifie la conversion des horodatages iCloud ; vérifiez donc les dates de la version d’origine avant de vous fier à un export.

Rechercher dans le texte de tous les messages

  1. Cliquez sur la loupe de la barre d’outils pour ouvrir Full-Text Search.
  2. Saisissez un ou plusieurs mots et appuyez sur Retour. La recherche examinée s’exécute lors de la validation du champ.
  3. Lisez l’expéditeur, la date et l’aperçu. Choisissez un résultat pour ouvrir sa discussion.

La recherche couvre le texte stocké et les noms d’expéditeurs au moyen d’un index de mots et préfixes. Elle renvoie au maximum les 100 correspondances les plus récentes. Il ne s’agit pas d’une recherche libre de fragments à n’importe quelle position : expressions partielles, ponctuation et langues sans espaces entre les mots peuvent se comporter autrement que prévu. Essayez une expression distinctive plus longue ou un autre terme.

Choisir un résultat sélectionne la conversation, pas le message exact trouvé. Pour un ancien résultat, prenez sa date comme repère et chargez des pages antérieures. La recherche n’examine pas les photos, les enregistrements vocaux, le contenu des pièces jointes ou le texte dessiné dans les stickers. Un résultat vide ne prouve pas que la sauvegarde source ne contient pas la conversation.

Images, pièces jointes, stickers et réactions

Reconnaître un type de message ne signifie pas conserver sa pièce jointe. Dans 1.0.0, les photos, vidéos, sons, fichiers, lieux, contacts et stickers sont représentés par du texte ou des libellés de type. L’interface examinée ne possède pas de téléchargement général des pièces jointes, de visionneuse photo ou de lecteur audio/vidéo.

Si votre application possède l’interface de 2.0

Pour les enregistrements de stickers iCloud compatibles, l’application lit les identifiants et demande un PNG au CDN de stickers de LINE. Les images chargées correctement sont mises en cache localement. Il s’agit d’une image fixe ; animation, son, stickers indisponibles et tous les formats plus récents ne sont pas garantis.

Les images déjà en cache peuvent être réutilisées hors ligne ; les autres nécessitent une requête réseau réussie. Un substitut peut indiquer des métadonnées manquantes, une absence de connexion ou une image CDN indisponible. Importer l’historique ne télécharge pas préalablement tous les stickers.

Les types de réactions pris en charge peuvent apparaître comme des emojis et des compteurs depuis la base complémentaire d’iCloud. Ces indicateurs ne sont pas un relevé complet de qui a réagi ni à quel moment. Ni les stickers ni les réactions ne font de ChatArchive une sauvegarde complète des médias.

Où votre archive est stockée

L’historique importé est enregistré automatiquement dans ~/Library/Application Support/ChatArchive/chatarchive.sqlite. L’importation normale ne demande pas de choisir l’emplacement de la base. Celle-ci peut avoir des fichiers annexes -wal et -shm. Gardez le dossier entier lors d’une sauvegarde.

Dans 2.0, les PNG de stickers téléchargés sont stockés dans ~/Library/Application Support/ChatArchive/StickerCache/. Les exports sont enregistrés à l’emplacement choisi dans la fenêtre de sauvegarde ; ce sont des copies distinctes, non mises à jour lors d’une nouvelle importation.

La base locale et les exports de lecture ne sont pas protégés par un chiffrement propre à ChatArchive ni par un mot de passe de l’application. Protégez-les avec le compte Mac, le chiffrement de l’appareil et un emplacement de sauvegarde approprié. Un fichier placé dans un dossier synchronisé avec le cloud peut être téléversé par ce service.

La base de l’application est une bibliothèque de travail, pas un paquet de restauration compatible avec LINE. Les anciennes références à .chatarchive ou .linearchive ne prouvent pas l’existence d’une commande d’importation/restauration dans ces interfaces Mac examinées.

Enregistrer des copies texte dans 1.0.0

Une conversation

Sélectionnez une discussion puis Save as Text au-dessus des messages. Choisissez le nom et la destination. Cette opération ne nécessite pas de licence d’exportation activée et lit tous les messages importés de la discussion, y compris les anciennes pages non encore affichées.

Toutes les conversations

Choisissez Export All dans la barre latérale. Une licence activée est requise. L’interface examinée de 1.0.0 demande un dossier de destination et crée un fichier texte pour chaque discussion non vide. Dans l’interface de 2.0, la même commande enregistre plutôt chatarchive-export.tar.gz, contenant des fichiers texte par discussion.

La sortie texte comprend dates, heures, noms d’expéditeurs et texte stocké. Elle n’intègre pas les fichiers binaires joints, les images de stickers ou les indicateurs de réactions. Un message non textuel sans texte stocké peut donc laisser très peu de contenu utile.

Examinez les conversations importantes exportées avant de vous y fier. Les noms de discussions deviennent des noms de fichiers : des noms identiques, ou rendus identiques par le remplacement de caractères interdits ou le raccourcissement de noms longs, peuvent entrer en conflit. Enregistrez ces discussions séparément avec des noms de fichiers différents.

HTML et Markdown : uniquement avec l’interface de 2.0

Attention au HTML : Dans l’implémentation examinée de 2.0, des fragments HTML présents dans les conversations peuvent modifier le comportement de la page exportée. Utilisez le texte ou Markdown tant qu’une version corrigée n’a pas été confirmée. Les étapes suivantes décrivent l’interface et ne recommandent pas d’ouvrir un export HTML issu de cette implémentation.

Ces formats sont présents dans le code examiné de 2.0, pas dans l’interface de la version vérifiée 1.0.0. Si votre application possède le bouton Export Chat dans la barre d’outils, sélectionnez d’abord une discussion, ouvrez ce bouton, puis choisissez le format et l’étendue.

Choix d’exportation de 2.0
ChoixLicenceSortie
Discussion sélectionnée → HTMLAucune licence activée requiseUn fichier HTML lisible dans un navigateur
Toutes les discussions → HTMLLicence activée requiseUn fichier HTML avec une liste de discussions
Markdown (ZIP)Licence activée requiseToutes les discussions en Markdown avec les fichiers de stickers en cache

HTML utilise All Chats par défaut. Pour exporter une seule discussion, choisissez explicitement Selected Chat. Enregistrez le fichier et attendez la fin ; l’application ouvre le résultat avec le programme associé.

HTML n’intègre que les images de stickers déjà en cache. Affichez correctement les stickers concernés avant l’export si vous avez besoin de leurs images. Son champ de recherche filtre les noms de discussions, pas tous les corps de messages, et JavaScript est nécessaire pour afficher les conversations.

Markdown ZIP inclut un dossier attachments/stickers/ et des références d’images de style Obsidian. Les lecteurs Markdown génériques peuvent nécessiter des adaptations de chemins ou de syntaxe. Vérifiez les images manquantes et les fichiers de discussions portant le même nom. Aucun format n’est une copie de préservation complète ou un fichier d’importation pour LINE. Conservez aussi la sauvegarde de la base.

Acheter et activer une licence d’exportation

Dans le code examiné, la lecture, la recherche et l’enregistrement d’une discussion en texte sont disponibles sans activation de l’exportation. L’exportation groupée en texte exige une activation. Les règles supplémentaires des formats de 2.0 figurent ci-dessus. Un achat et une activation réussie sont deux étapes distinctes.

  1. Consultez les détails d’achat et de livraison sur la page actuelle du produit.
  2. Ouvrez Activate License dans ChatArchive et saisissez la clé compatible fournie pour le produit.
  3. Activez avec une connexion Internet et vérifiez l’état obtenu. Conservez le reçu d’achat de façon privée.

Les deux versions examinées utilisent le service de licences Lemon Squeezy, même si le lien d’achat ultérieur pointe vers Gumroad. Un reçu Gumroad ne démontre pas à lui seul la compatibilité d’une clé. Si la clé manque ou est refusée, contactez l’assistance avec la référence de commande ; ne rachetez pas le produit simplement pour tenter de résoudre le problème.

License Management permet de désactiver cette installation pour libérer son activation. Cette opération ne supprime pas de conversations et n’effectue aucun remboursement. La désactivation nécessite une réponse positive du service.

Stockage local et activité réseau

Le traitement local des conversations ne signifie pas que l’application ne communique jamais. Les comportements suivants existent dans l’implémentation examinée.

Quand des communications peuvent avoir lieu
OpérationComportement
Lecture et recherche de discussionsLes conversations stockées sont traitées sur le Mac ; aucun point d’envoi de conversations n’a été trouvé dans les chemins examinés.
Importation iCloudmacOS peut télécharger la sauvegarde LINE depuis iCloud. Le compte Apple et l’activité iCloud sont gérés par les services Apple.
Service de licencesL’activation envoie la clé de licence et le nom du Mac à Lemon Squeezy. La validation/désactivation envoie la clé et l’identifiant de l’instance d’activation.
Chargement de stickers dans 2.0Les requêtes vers le CDN de LINE identifient le sticker ; le serveur reçoit aussi les données habituelles de connexion, comme l’adresse IP.
Liens et fichiers enregistrésOuvrir des sites, acheter l’application ou enregistrer dans des dossiers synchronisés peut faire intervenir d’autres services.

Une installation activée peut vérifier sa licence au démarrage après 7 jours depuis l’activation ou la dernière validation réussie. Une erreur réseau conserve l’état précédent d’activation dans l’implémentation examinée ; une réponse de licence invalide peut désactiver les exports payants. Cela ne garantit pas une activation hors ligne permanente.

Les identifiants de licence sont stockés dans le Trousseau de macOS. La base de conversations est un fichier local séparé. Le texte déjà importé peut être lu sans récupérer la source à nouveau, mais les premiers téléchargements iCloud, l’activation et les stickers de 2.0 non encore en cache peuvent demander une connexion.

Sauvegarder et supprimer les données

Avant une nouvelle importation ou un changement de Mac

  1. Quittez complètement ChatArchive.
  2. Dans le Finder, choisissez Aller → Aller au dossier et saisissez ~/Library/Application Support/ChatArchive/.
  3. Copiez le dossier entier vers un emplacement protégé et daté. Incluez les fichiers annexes de la base et le cache des stickers.
  4. Conservez séparément les exports de lecture importants et la sauvegarde source d’origine. Vérifiez l’existence de votre copie avant de poursuivre.

Cela préserve les fichiers locaux ; l’interface examinée n’a ni assistant de restauration de base officiellement pris en charge ni fusion de bibliothèques. Pour migrer ou récupérer, laissez la copie originale intacte et demandez à l’assistance les compatibilités entre versions. Une activation de licence séparée peut aussi être nécessaire sur un autre Mac.

Supprimer l’historique local

L’interface examinée n’a pas de commande de suppression par discussion. Après avoir quitté l’application et effectué la sauvegarde nécessaire, vous pouvez déplacer le dossier ChatArchive d’Application Support vers la Corbeille dans le Finder. La suppression effective des fichiers retire la bibliothèque locale de travail ; un lancement ultérieur crée une bibliothèque vide. Supprimez séparément les exports et copies de sauvegarde si vous le souhaitez.

Supprimer uniquement l’application ne retire pas nécessairement ses fichiers Application Support ou sa licence dans le Trousseau. Supprimer les fichiers ChatArchive n’efface ni les conversations LINE d’origine ni la sauvegarde iCloud. Corbeille, sauvegardes système et copies cloud ont leurs propres règles de conservation ; il ne s’agit pas d’une fonction d’effacement sécurisé.

Contactez hakaruapps-contact@hakaru.net en indiquant version/build de ChatArchive, version de macOS, version de LINE si pertinente, parcours d’importation, erreur exacte et étapes courtes de reproduction. Précisez si le problème survient avant ou après la fin de l’importation.

Commencez par une description plutôt que d’envoyer une base de conversations, un ZIP de sauvegarde, une clé de licence ou des captures privées. Si des exemples sont nécessaires, retirez noms, textes de conversations, chemins contenant des détails personnels et identifiants. Ce manuel résulte de l’examen de métadonnées de distribution et du code source ; ce n’est pas un test d’importation réelle avec toutes les versions actuelles de LINE.
