먼저 확인할 사항: 버전과 용도

ChatArchive는 LINE 대화를 읽을 수 있는 사본으로 보관하는 Mac 앱입니다. 가져오기 원본에 남아 있는 기록을 자체 로컬 데이터베이스로 가져와 대화를 표시하고 메시지 본문을 검색합니다. LINE으로 대화를 복원하거나, LINE 계정을 이전하거나, 메시지를 보내거나, 원본에 없는 내용을 복구하는 도구는 아닙니다.

이 설명서는 2026년 11월 15일에 확인했습니다. 배포 파일을 확인한 릴리스는 1.0.0(build 1)이며 macOS 14.0 이상이 필요합니다. 디스크 이미지의 버전 정보와 해당 소스를 검토했습니다. 현재 Gumroad 판매 페이지에는 제공되는 실행 파일의 버전이 없으므로, 해당 다운로드가 이 릴리스와 같은지는 확인되지 않았습니다.

별도의 2.0.0(build 2) 소스에서 추가된 기능은 아래에서 “앱에 2.0 화면이 있는 경우”로 구분합니다. 개발 버전 번호만으로 구매 시 그 기능이 제공된다고 판단할 수는 없습니다. Finder의 정보 가져오기에서 설치한 앱 버전을 확인하고 실제 표시되는 조작에 맞춰 진행하세요.

앱 인터페이스는 영어, 일본어, 중국어 번체, 태국어를 지원합니다. 이 설명서의 제공 언어와는 별개입니다. 소스 관련 설명은 개발자가 비공개 저장소를 검토한 결과이며, 공개 코드 다운로드 링크를 뜻하지 않습니다.

설치와 원본 선택

  1. 공식 구매·다운로드 경로에서 ChatArchive를 받습니다. DMG로 제공되면 열어서 ChatArchive를 응용 프로그램 폴더에 복사한 뒤 실행합니다.
  2. 가져온 데이터베이스, 임시 압축 해제 파일, 내보내기 파일을 위한 Mac 저장 공간을 확보합니다. 필요한 용량은 기록마다 다릅니다.
  3. Mac용 LINE의 로컬 데이터베이스 또는 호환되는 iPhone용 LINE의 iCloud 백업을 선택합니다. 두 원본에 담긴 기간과 메시지 수는 다를 수 있습니다.
  4. 기존 ChatArchive 라이브러리를 교체하기 전에 백업과 데이터 삭제 절차를 따르세요.

Mac에서 가져오려면 Mac용 LINE을 설치하고 LINE에서 로그인한 뒤 실행 상태로 둡니다. iCloud에서 가져오려면 Mac의 iCloud Drive 계정으로 해당 백업에 접근할 수 있어야 합니다. ChatArchive 자체에는 LINE 또는 Apple 계정 로그인 화면이 없습니다.

검토한 앱은 macOS 전용입니다. Android/Google Drive 백업, Finder의 일반 iPhone 기기 백업, 임의 ZIP 파일은 읽지 않습니다. 이후 모든 LINE 데이터베이스나 백업 형식과의 호환성을 보장하지 않습니다.

1.0.0에서 Mac용 LINE 기록 가져오기

  1. Mac용 LINE을 열고 로그인을 완료합니다. 원하는 계정인지 확인한 뒤 LINE을 열어 둡니다.
  2. 권한을 요청하면 macOS 시스템 설정 → 개인정보 보호 및 보안 → 개발자 도구에서 ChatArchive를 허용합니다. 실행 중인 LINE 프로세스에 접근하기 위한 권한입니다.
  3. ChatArchive에서 Import from LINE을 선택한 뒤 Import from LINE for Mac을 선택합니다.
  4. 탐색, 키 가져오기, 데이터베이스 읽기, 가져오기가 끝날 때까지 기다립니다. 도중에 계정을 바꾸거나 LINE을 종료하지 마세요.
  5. 완료 건수를 확인하고 창을 닫은 뒤 여러 대화와 날짜를 살펴봅니다.

앱은 실행 중인 프로세스에서 얻은 키로 LINE의 로컬 암호화 데이터베이스를 읽습니다. 원본 데이터베이스는 읽기 전용으로 엽니다. LINE 서버에 전체 과거 대화를 요청하는 방식은 아닙니다. 후보 데이터베이스가 여러 개라면 큰 데이터베이스를 우선 탐색하며, 일반적인 계정 선택 화면은 없습니다.

전체 디스크 접근 권한은 개발자 도구 권한을 대신하지 않습니다. 안내된 권한을 허용한 후에도 접근이나 복호화가 실패하면 시스템 보호를 끄지 말고 지원팀에 문의하세요. 2.0 화면에서 Mac 가져오기는 숨겨진 개발자 기능입니다. 그 버전에서는 일반 iCloud 경로를 이용하세요.

iPhone LINE의 iCloud 백업 가져오기

이 경로는 검토한 1.0.0 화면에서도 제공되며 2.0 화면에서는 기본 가져오기 경로입니다. 기기 전체 iCloud 백업이 아니라 LINE 전용 archive.zip을 읽습니다.

  1. iPhone의 LINE에 목적에 맞는 표준 백업이 완료되어 있는지 확인합니다. 현재 휴대전화 조작은 LINE 공식 백업 안내를 따르세요.
  2. Mac에서 해당 백업에 접근할 수 있는 Apple 계정을 사용하고 iCloud Drive를 켭니다. 인터넷에 연결한 뒤 파일을 사용할 수 있을 때까지 기다립니다.
  3. Import from LINE → Import from iCloud Backup을 선택합니다.
  4. 다운로드, 압축 해제, 가져오기가 끝나면 건수·이름·날짜를 확인합니다. 이후 인터페이스에는 Imported from도 표시됩니다.

탐색 위치는 ~/Library/Mobile Documents/iCloud~com~linecorp~line/Data-*/Backup/archive.zip입니다. 날짜나 계정 선택 화면 없이 처음 발견한 백업을 사용하며, 최신 백업을 고른다고 보장하지 않습니다. 이 경로에서는 Mac용 LINE을 실행할 필요가 없고, iCloud 읽기에 개발자 도구 권한도 사용하지 않습니다.

가져오는 기록의 범위

아카이브에는 가져오기 시점에 선택된 원본에 존재하는 기록이 반영됩니다. 성공했다고 해서 계정에서 주고받은 모든 대화가 포함되었다는 뜻은 아닙니다. 이전에 삭제된 메시지, 이용할 수 없는 오래된 기록, 원본에 없는 미디어는 재구성할 수 없습니다.

iCloud 읽기는 예상한 테이블이 있을 때 일대일 대화, 여러 사람 대화, 그룹, 공식 계정, Keep Memo를 처리합니다. 연락처 정보가 없으면 이름 대신 식별자나 일반 이름이 나올 수 있습니다. 알 수 없는 메시지 유형은 유형 번호로 표시될 수 있습니다.

Mac과 iCloud 사본은 독립적인 원본입니다. 휴대전화에 보이는 기록을 Mac이 저장한 적이 없을 수도 있습니다. 다른 원본을 가져오면 현재 ChatArchive 라이브러리를 교체하며 두 범위를 합치지는 않습니다.

완전성이 중요하다면 원본 백업도 따로 보관하세요. 앱은 선택된 필드를 읽으며 LINE 데이터베이스의 모든 테이블과 메타데이터를 저장하지 않습니다. 특히 2.0의 반응 추출은 백업의 SQLite 저널 파일을 포함하지 않으므로 모든 반응이 갖춰진다고 보장할 수 없습니다.

기록 업데이트: 누적이 아닌 교체

Mac/iCloud에서 가져올 때마다 ChatArchive의 연락처, 채팅, 메시지 라이브러리 전체를 교체합니다. 검토한 두 버전 모두에 해당합니다. 더 새롭거나 오래된 원본 또는 다른 원본을 가져오기 전에 별도 사본을 저장하세요. 병합 모드, 증분 다운로드, 자동 예약 동기화는 없습니다.

  1. 현재 로컬 라이브러리를 백업하고 필요한 읽기용 사본을 저장합니다.
  2. 원하는 원본과 백업 기간을 확인합니다.
  3. 같은 가져오기 절차를 다시 실행합니다.
  4. 가장 오래된 날짜와 최신 날짜, 중요한 대화, 완료 건수를 예상과 비교합니다.

가져오기는 하나의 데이터베이스 트랜잭션 안에서 실행됩니다. 그 안에서 데이터베이스 오류가 발생하면 변경 사항을 되돌립니다. 유용한 보호 장치지만 사용자 백업을 대신하지는 않습니다.

같은 원본을 다시 가져온다고 기존 메시지마다 두 번째 사본을 덧붙이지는 않습니다. 원본을 기준으로 라이브러리를 다시 만들기 때문에 원본 자체의 중복은 남을 수 있습니다. 더 작은 원본을 가져오면 라이브러리가 줄어들고 이전에 보이던 기록이 사라질 수 있습니다.

대화와 이전 메시지 보기

왼쪽 사이드바에는 가져오기, 내보내기, 라이선스 조작이 있습니다. 가운데에는 마지막 메시지 시간순으로 채팅이 표시됩니다. 채팅을 선택하면 오른쪽에서 읽을 수 있습니다. 채팅 목록 검색 칸은 채팅 이름을 필터링하며 메시지 본문은 검색하지 않습니다.

대화를 열면 우선 최신 200개 메시지를 불러옵니다. 위쪽의 Load older messages를 사용하면 이전 페이지를 한 번에 최대 200개씩 추가합니다. 화면에 최근 기간만 보여도 가져온 과거 메시지가 없다는 뜻은 아닙니다.

메시지는 날짜별로 묶이고 내 메시지와 다른 발신자의 메시지를 구분합니다. 텍스트를 선택해 복사할 수 있습니다. 2.0 화면에서는 감지된 링크를 시스템 브라우저나 연결된 앱으로 열 수 있습니다. 링크 열기는 로컬 아카이브 읽기와 별도의 동작입니다.

날짜가 이상하다면 원본을 보관하고 버전과 가져오기 경로를 알려 주세요. 1.0.0 이후 소스는 iCloud 시간 변환 방식을 바꾸므로, 초기 릴리스에서 내보낸 파일을 신뢰하기 전에 날짜를 확인해야 합니다.

메시지 본문 전체 검색

  1. 도구 막대의 돋보기를 클릭해 Full-Text Search를 엽니다.
  2. 단어나 여러 단어를 입력하고 Return을 누릅니다. 검토한 검색은 입력을 제출할 때 실행됩니다.
  3. 발신자, 날짜, 메시지 미리보기를 확인하고 결과를 선택해 해당 채팅을 엽니다.

저장된 본문과 발신자 이름을 단어·접두어 인덱스로 검색합니다. 최신 순으로 최대 100개 결과를 반환합니다. 아무 위치의 부분 문자열이나 찾는 검색은 아니므로, 구절 일부, 문장부호, 단어 사이에 공백을 쓰지 않는 언어는 기대와 다를 수 있습니다. 특징적인 긴 표현이나 다른 검색어를 시도하세요.

결과를 선택하면 대화가 선택될 뿐 정확히 일치한 메시지 위치로 이동하지는 않습니다. 오래된 결과라면 날짜를 참고해 이전 페이지를 불러오세요. 사진, 음성 녹음, 첨부 내용, 스티커 그림 속 글자는 검색하지 않습니다. 결과가 없다고 원본 백업에도 대화가 없다는 뜻은 아닙니다.

이미지, 첨부, 스티커와 반응

메시지 유형을 인식하는 것과 첨부 자체를 보관하는 것은 다릅니다. 1.0.0에서는 사진, 동영상, 음성, 파일, 위치, 연락처, 스티커가 텍스트나 유형 이름으로 표시됩니다. 검토한 화면에는 일반 첨부 다운로드, 사진 뷰어, 음성·동영상 플레이어가 없습니다.

앱에 2.0 화면이 있는 경우

호환되는 iCloud 스티커 기록에서 식별자를 읽고 LINE 스티커 CDN에 PNG를 요청합니다. 불러온 이미지는 로컬에 캐시됩니다. 정지 이미지 표현이며, 애니메이션, 소리, 제공 중단 스티커, 모든 최신 형식을 보장하지 않습니다.

이미 캐시된 이미지는 오프라인에서도 재사용하지만, 없는 이미지는 네트워크 요청에 성공해야 합니다. 대체 표시는 메타데이터 부족, 연결 없음, CDN 이미지 이용 불가 때문일 수 있습니다. 기록만 가져온다고 모든 스티커를 미리 내려받지는 않습니다.

지원되는 반응 유형은 iCloud 보조 데이터베이스에서 이모지 배지와 개수로 표시할 수 있습니다. 누가 언제 반응했는지를 모두 담은 기록은 아닙니다. 스티커와 반응이 표시되어도 ChatArchive가 완전한 미디어 백업이 되는 것은 아닙니다.

아카이브 저장 위치

가져온 기록은 ~/Library/Application Support/ChatArchive/chatarchive.sqlite에 자동 저장됩니다. 일반 가져오기에서는 데이터베이스 위치를 묻지 않습니다. 데이터베이스에는 -wal과 -shm 동반 파일이 있을 수 있으므로 백업할 때 폴더를 함께 보관하세요.

2.0에서 내려받은 스티커 PNG는 ~/Library/Application Support/ChatArchive/StickerCache/에 저장됩니다. 내보내기 파일은 저장 대화상자에서 선택한 위치에 별도 사본으로 저장되며, 다시 가져와도 갱신되지 않습니다.

로컬 데이터베이스와 읽기용 내보내기 파일에는 ChatArchive 전용 암호화나 앱 암호가 적용되지 않습니다. Mac 계정, 기기 암호화, 적절한 백업 위치로 보호하세요. 클라우드 동기화 폴더에 저장하면 해당 서비스가 파일을 업로드할 수 있습니다.

앱의 데이터베이스는 작업용 라이브러리이며 LINE 호환 복원 패키지가 아닙니다. 오래된 문서의 .chatarchive 또는 .linearchive 언급만으로 검토한 Mac 화면에 가져오기·복원 명령이 있다고 판단할 수 없습니다.

1.0.0에서 텍스트 사본 저장

대화 하나

채팅을 선택하고 메시지 위의 Save as Text를 누른 뒤 파일 이름과 위치를 정합니다. 내보내기 라이선스 활성화가 필요하지 않으며, 아직 화면에 표시하지 않은 이전 페이지까지 해당 채팅의 가져온 메시지 전체를 읽습니다.

모든 대화

사이드바에서 Export All을 선택합니다. 활성화된 라이선스가 필요합니다. 검토한 1.0.0 화면은 대상 폴더를 선택한 뒤 비어 있지 않은 채팅마다 텍스트 파일을 만듭니다. 2.0 화면에서는 같은 사이드바 조작으로 채팅별 텍스트를 담은 chatarchive-export.tar.gz를 저장합니다.

텍스트에는 날짜, 시간, 발신자 이름, 저장된 본문이 포함됩니다. 첨부 바이너리, 스티커 이미지, 반응 배지는 포함하지 않습니다. 저장된 본문이 없는 비텍스트 메시지는 유용한 내용이 거의 남지 않을 수 있습니다.

중요한 대화는 내보낸 내용을 확인한 뒤 의존하세요. 채팅 이름이 파일 이름이 되므로 동명이거나, 금지 문자 치환 또는 긴 이름 단축 후 같아지는 이름은 충돌할 수 있습니다. 이런 채팅은 서로 다른 파일 이름으로 개별 저장하세요.

HTML과 Markdown: 2.0 화면이 있을 때만

HTML 주의: 검토한 2.0 구현에서는 대화 본문의 HTML 조각이 내보낸 페이지 동작에 영향을 줄 수 있습니다. 수정된 버전을 확인하기 전에는 텍스트 또는 Markdown을 사용하세요. 아래 절차는 인터페이스 설명이며, 이 구현에서 만든 HTML 파일을 열도록 권장하는 내용이 아닙니다.

이 형식은 검토한 2.0 소스에 있으며, 배포를 확인한 1.0.0 화면에는 없습니다. 도구 막대에 Export Chat 버튼이 있다면 먼저 채팅을 선택하고 버튼을 연 뒤 형식과 범위를 고릅니다.

HTML은 이미 캐시에 있는 스티커 이미지만 포함합니다. 이미지가 필요하면 해당 스티커를 정상 표시한 뒤 내보내세요. 검색 칸은 채팅 이름만 필터링하며 전체 본문을 검색하지 않습니다. 대화를 표시하려면 JavaScript가 필요합니다.

Markdown ZIP에는 attachments/stickers/ 폴더와 Obsidian 형식의 이미지 참조가 들어갑니다. 일반 Markdown 뷰어에서는 경로나 문법 조정이 필요할 수 있습니다. 누락된 이미지와 같은 이름의 채팅 파일을 확인하세요. 두 형식 모두 완전한 보존 사본이나 LINE용 가져오기 파일은 아니므로 데이터베이스 백업도 보관하세요.

내보내기 라이선스 구매와 활성화

검토한 코드에서는 읽기, 검색, 채팅 하나의 텍스트 저장에 내보내기 활성화가 필요하지 않습니다. 텍스트 일괄 내보내기는 활성화가 필요합니다. 2.0 추가 형식의 조건은 앞의 표를 확인하세요. 구매와 활성화 성공은 별개의 단계입니다.

  1. 현재 상품 페이지에서 구매와 제공 내용을 확인합니다.
  2. ChatArchive의 Activate License를 열고 제품용으로 제공된 호환 라이선스 키를 입력합니다.
  3. 온라인에서 활성화한 뒤 결과 상태를 확인합니다. 구매 영수증은 비공개로 보관하세요.

검토한 두 버전 모두 Lemon Squeezy 라이선스 서비스를 사용하며, 이후 구매 링크가 Gumroad를 가리켜도 이 점은 같습니다. Gumroad 영수증만으로 키 호환성을 확인할 수는 없습니다. 키가 없거나 거절되면 주문 정보를 첨부해 지원팀에 문의하고, 문제 해결만을 위해 다시 구매하지 마세요.

License Management에서는 이 설치의 활성화를 해제할 수 있습니다. 대화를 삭제하거나 환불하는 기능은 아닙니다. 해제하려면 서비스의 정상 응답이 필요합니다.

라이선스 자격 증명은 macOS 키체인에 보관됩니다. 대화 데이터베이스는 별도 로컬 파일입니다. 이미 가져온 본문은 원본을 다시 받지 않고 읽을 수 있지만, 첫 iCloud 다운로드, 활성화, 캐시되지 않은 2.0 스티커에는 연결이 필요할 수 있습니다.

백업과 데이터 삭제

다시 가져오거나 Mac을 옮기기 전에

  1. ChatArchive를 완전히 종료합니다.
  2. Finder에서 이동 → 폴더로 이동을 열고 ~/Library/Application Support/ChatArchive/를 입력합니다.
  3. 폴더 전체를 날짜를 붙인 보호된 백업 위치에 복사합니다. 데이터베이스 동반 파일과 스티커 캐시도 포함하세요.
  4. 중요한 읽기용 파일과 원본 백업은 별도로 보관합니다. 다음 단계로 넘어가기 전에 백업 사본이 실제로 있는지 확인합니다.

이는 로컬 파일을 보존하는 절차입니다. 검토한 UI에는 지원되는 데이터베이스 복원 마법사나 라이브러리 병합 기능이 없습니다. 이전·복구 시 원본 사본을 변경하지 말고 버전 호환성을 지원팀에 문의하세요. 다른 Mac에서는 라이선스도 별도로 활성화해야 할 수 있습니다.

로컬 기록 삭제

검토한 인터페이스에는 채팅별 삭제 명령이 없습니다. 종료하고 필요한 백업을 만든 뒤 Finder에서 Application Support의 ChatArchive 폴더를 휴지통으로 옮길 수 있습니다. 실제 파일을 삭제하면 로컬 작업용 라이브러리가 없어지고, 다음 실행 때 새 빈 라이브러리를 만듭니다. 내보낸 파일과 백업은 필요하면 따로 삭제하세요.

앱만 삭제해도 Application Support 파일이나 키체인 라이선스가 반드시 삭제되는 것은 아닙니다. ChatArchive 파일 삭제는 원래 LINE 대화나 iCloud 백업을 지우지 않습니다. 휴지통, 시스템 백업, 클라우드 사본에는 각자의 보존 방식이 있으므로 안전한 완전 삭제 기능은 아닙니다.
