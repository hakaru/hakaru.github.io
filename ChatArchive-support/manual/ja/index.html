最初に確認すること：対象版と用途

ChatArchive は、LINE の会話を読み返せる形で保存する Mac アプリです。取得元に残っている履歴を独自のローカルデータベースへ読み込み、会話の表示とメッセージ本文の検索を行います。LINE への復元、LINE アカウントの移行、メッセージ送信、取得元に存在しない内容の復旧を行うツールではありません。

このマニュアルは 2026年11月15日に確認しました。配布ファイルを確認できたリリースは 1.0.0（build 1）、macOS 14.0 以降です。ディスクイメージ内の版情報と対応するソースを確認しています。現在の Gumroad 販売ページには納品されるアプリの版番号がなく、このリリースとの同一性は確認できていません。

別に存在する 2.0.0（build 2） のソースで追加された機能は、以下で「2.0 の画面が表示される場合」と明記します。開発版の番号だけでは、購入時にその機能が提供されることを確認できません。Finder の「情報を見る」で手元のアプリの版を確認し、実際にある操作項目に合わせて進めてください。

アプリの表示言語は英語、日本語、繁体字中国語、タイ語です。このマニュアルの提供言語とは別です。ソースに関する記述は、開発者による非公開リポジトリの確認結果を示すもので、公開コードへのリンクではありません。

インストールと取得元の選択

  1. 公式の購入・ダウンロード窓口から ChatArchive を入手します。DMG 形式の場合は開き、ChatArchive を「アプリケーション」へコピーしてから起動します。
  2. 読み込み後のデータベース、展開用の一時ファイル、書き出し先のために Mac の空き容量を確保します。必要量は履歴によって異なります。
  3. Mac 版 LINE のローカルデータベースか、対応する iPhone 版 LINE の iCloud バックアップを選びます。両者に含まれる期間やメッセージ数は同じとは限りません。
  4. 既存の ChatArchive の履歴を入れ替える前に、バックアップとデータの削除を確認します。

Mac からの読み込みには、LINE for Mac をインストールし、LINE 上でログインして起動したままにします。iCloud からの読み込みには、対象のバックアップへ Mac の iCloud Drive アカウントからアクセスできる必要があります。ChatArchive 自体に LINE や Apple Account のログイン画面はありません。

確認したアプリは macOS 専用です。Android／Google Drive のバックアップ、Finder が作成する iPhone 全体のバックアップ、任意の ZIP ファイルには対応しません。将来のすべての LINE データベース形式やバックアップ形式に対応する保証はありません。

1.0.0 で Mac 版 LINE から読み込む

  1. LINE for Mac を開いてログインを完了します。目的のアカウントであることを確認し、LINE を開いたままにします。
  2. 許可を求められた場合は、macOS の「システム設定」→「プライバシーとセキュリティ」→「開発者ツール」で ChatArchive を許可します。これは起動中の LINE プロセスへアクセスするための権限です。
  3. ChatArchive で「LINE から読み込む」→「LINE for Mac から読み込む」を選びます。
  4. 検出、キー取得、データベースの読み取り、取り込みが終わるまで待ちます。途中でアカウントを切り替えたり LINE を終了したりしないでください。
  5. 完了時の件数を確認して画面を閉じ、複数の会話と日付を確かめます。

アプリは、起動中のプロセスから得たキーを使って LINE のローカル暗号化データベースを読みます。元データベースは読み取り専用で開きます。LINE のサーバーへ全期間の会話を取りに行く処理ではありません。候補が複数あるときは大きいデータベースを優先して自動検出し、この画面に通常のアカウント選択機能はありません。

フルディスクアクセスは、開発者ツール権限の代わりにはなりません。案内どおりの許可をしてもアクセスや復号に失敗する場合は、システムの保護を無効にせずサポートへ連絡してください。2.0 の画面では Mac からの読み込みは開発者向けの非表示機能です。通常の iCloud の経路を使ってください。

iPhone 版 LINE の iCloud バックアップを読み込む

この経路は確認した 1.0.0 の画面にあり、2.0 の画面では通常の読み込み方法です。iPhone 全体の iCloud バックアップではなく、LINE 専用の archive.zip を読みます。

  1. iPhone の LINE に、完了済みで目的に合った標準バックアップがあることを確認します。スマートフォン側の現在の操作は、LINE 公式のバックアップ手順を参照してください。
  2. Mac ではそのバックアップへアクセスできる Apple Account を使い、iCloud Drive を有効にします。インターネットに接続し、ファイルが利用可能になるまで待ちます。
  3. 「LINE から読み込む」→「iCloud バックアップから読み込む」を選びます。
  4. ダウンロード、展開、取り込みを待ち、結果の件数、名前、日付を確認します。後の画面では「読み込み元」も表示されます。

検出対象は ~/Library/Mobile Documents/iCloud~com~linecorp~line/Data-*/Backup/archive.zip です。最初に見つかったバックアップを選び、日付やアカウントを選ぶ画面はありません。最新のものが選ばれる保証もありません。この経路では Mac 版 LINE を起動する必要はなく、iCloud の読み取りに開発者ツール権限は使いません。

取り込まれる履歴の範囲

アーカイブに含まれるのは、読み込み時点で選択された取得元に存在する記録です。取り込みの成功は、そのアカウントで過去に交わしたすべての会話が含まれることを意味しません。以前に削除されたメッセージ、取得できない古い履歴、取得元にないメディアを再構築することはできません。

iCloud の読み取りでは、想定するテーブルがある場合に、個別トーク、複数人トーク、グループ、公式アカウント、Keep Memo を扱います。連絡先情報がない場合は、名前の代わりに識別子や一般的な名称が表示されることがあります。未知のメッセージ形式は形式番号で表示される場合があります。

Mac と iCloud は独立した取得元です。スマートフォンに見える履歴が Mac に保存されているとは限りません。別の取得元を読み込むと現在の ChatArchive の履歴を置き換え、両者の範囲を統合することはありません。

完全性が重要な場合は、元のバックアップも別に保管してください。アプリは特定の項目を読み取り、LINE データベースの全テーブルや全メタデータを保存するわけではありません。特に 2.0 のリアクション読み取りはバックアップ内の SQLite ジャーナルファイルを取り込まないため、すべてのリアクションが揃う保証はありません。

履歴の更新：追記ではなく置き換え

Mac／iCloud から読み込むたびに、ChatArchive 内の連絡先、チャット、メッセージをすべて置き換えます。確認した両方の版に共通です。新しい取得元、古い取得元、別の取得元を読み込む前に、現在の内容を別に保存してください。統合モード、差分の取得、自動の定期同期はありません。

  1. 現在のローカル履歴をバックアップし、必要な閲覧用ファイルを書き出します。
  2. 目的の取得元とバックアップの対象期間を確認します。
  3. 同じ読み込み手順をもう一度実行します。
  4. 最古・最新の日付、大切な会話、完了時の件数が想定どおりか比較します。

取り込みはデータベースの単一トランザクションで行い、その途中でデータベースエラーが起きると変更を巻き戻します。ただし、手元のバックアップの代わりにはなりません。

同じ取得元を再度読み込んでも、既存の全メッセージにもう一組を追記する処理にはなりません。取得元から履歴を作り直すため、取得元自体にある重複は残る場合があります。件数の少ない取得元へ切り替えると、以前は表示されていた履歴がなくなることがあります。

会話と過去のメッセージを見る

左列に読み込み、書き出し、ライセンスの操作があります。中央列には最後のメッセージ日時順でチャットが並び、選択した会話を右列で読みます。チャット一覧の検索欄はチャット名を絞り込み、メッセージ本文は検索しません。

会話を開いた直後は最新の 200 件を読み込みます。上部の「過去のメッセージを読み込む」で、それより前の履歴を最大 200 件ずつ追加表示します。画面に最近の期間しか見えなくても、取り込み済みの古い履歴がないとは限りません。

メッセージは日付ごとにまとまり、自分の発言と相手の発言を区別します。文字は選択してコピーできます。2.0 の画面では、検出されたリンクからブラウザーや対応アプリを開けます。リンクを開く操作はローカルの履歴を読む操作とは別です。

不自然な日付が表示される場合は取得元を保存し、アプリの版と読み込み経路をサポートへ知らせてください。1.0.0 より後のソースでは iCloud の日時変換が変更されているため、元のリリースから書き出す前に日付を確認してください。

メッセージ本文を横断検索する

  1. ツールバーの虫眼鏡をクリックし、「全文検索」を開きます。
  2. 単語などを入力して Return キーを押します。確認した検索は入力の確定時に実行されます。
  3. 送信者、日時、本文の抜粋を確認し、結果を選ぶとそのチャットが開きます。

保存されたメッセージ本文と送信者名を、単語・前方一致の索引で検索します。返されるのは新しい順に最大 100 件です。任意の位置の部分文字列を探す検索ではなく、途中の語句、記号、単語間に空白を使わない言語などは想定と異なる場合があります。特徴的な長めの表現や別の語を試してください。

結果を選ぶと会話を開きますが、一致したメッセージそのものへ移動するわけではありません。古い結果は日付を目安に過去のページを読み込んで探します。写真、音声、添付ファイルの中身、スタンプ画像内の文字は検索しません。検索結果が空でも、元のバックアップに会話が存在しないとは限りません。

画像・添付・スタンプ・リアクション

メッセージの種類を識別することと、添付本体を保存することは別です。1.0.0 では写真、動画、音声、ファイル、位置情報、連絡先、スタンプを本文や種類ラベルとして表示します。確認した画面には、汎用の添付ダウンロード、写真ビューアー、音声・動画プレーヤーはありません。

2.0 の画面が表示される場合

対応する iCloud のスタンプ記録から識別子を読み取り、LINE のスタンプ CDN へ PNG 画像を要求します。取得できた画像はローカルにキャッシュします。静止画像での表示であり、アニメーション、音声、配信されなくなったスタンプ、新しいすべての形式には対応を保証しません。

キャッシュ済みの画像はオフラインで再利用できますが、未取得の画像には通信が必要です。代替表示になる理由には、メタデータ不足、未接続、CDN 画像を取得できない場合があります。履歴を読み込むだけで全スタンプを事前取得することはありません。

iCloud の補助データベースから、対応するリアクションを絵文字のバッジと件数で表示できます。誰がいつリアクションしたかの完全な記録ではありません。スタンプやリアクションが表示できても、ChatArchive がメディア全体のバックアップになるわけではありません。

保存される形式と場所

読み込んだ履歴は ~/Library/Application Support/ChatArchive/chatarchive.sqlite へ自動保存します。通常の読み込みでデータベースの保存先を選ぶ画面はありません。データベースには -wal と -shm の付属ファイルが存在する場合があります。バックアップではフォルダをまとめて保存してください。

2.0 では取得したスタンプの PNG を ~/Library/Application Support/ChatArchive/StickerCache/ に保存します。書き出したファイルは保存ダイアログで選んだ場所に置きます。独立したコピーなので、その後の読み込みで更新されません。

ローカルデータベースと閲覧用の書き出しファイルには、ChatArchive 独自の暗号化やアプリ用パスワードはありません。Mac のアカウント、デバイスの暗号化、適切なバックアップ先で保護してください。クラウド同期フォルダへ保存したファイルは、そのサービスによってアップロードされる場合があります。

アプリのデータベースは閲覧用のライブラリであり、LINE へ戻せる復元パッケージではありません。古い資料にある .chatarchive や .linearchive の記述だけで、確認した Mac の画面に読み込み・復元コマンドがあるとは判断できません。

1.0.0 でテキストを書き出す

一つの会話

チャットを選び、メッセージ上部の「テキストで保存」を選択して名前と保存先を決めます。この操作にエクスポートライセンスの認証は不要です。画面にまだ読み込んでいない古いページも含め、そのチャットの取り込み済みメッセージをすべて読み取ります。

すべての会話

左側の「全ファイルエクスポート」を選びます。認証済みライセンスが必要です。確認した 1.0.0 の画面では保存先フォルダを選択し、メッセージのあるチャットごとにテキストファイルを作成します。2.0 の画面では、同じ左側の操作からチャットごとのテキストを含む chatarchive-export.tar.gz を保存します。

テキストには日付、時刻、送信者名、保存された本文が含まれます。添付本体、スタンプ画像、リアクションのバッジは埋め込みません。本文のない非テキストメッセージは、内容がほとんど残らない場合があります。

大切な会話は書き出した内容を確認してから保管してください。チャット名がファイル名になるため、同名のチャットや、使用できない文字の置換・長い名前の短縮によって同名になるチャットは衝突する場合があります。そのような会話は個別に異なるファイル名で保存してください。

HTML と Markdown：2.0 の画面がある場合のみ

HTML の注意：確認した 2.0 の実装では、会話本文に含まれる HTML 断片が書き出したページの動作に影響する可能性があります。修正版を確認するまではテキストまたは Markdown を使ってください。以下は画面の説明であり、この実装からの HTML 書き出しを開くことを勧めるものではありません。

これらの形式は確認した 2.0 のソースにあり、配布ファイルを確認した 1.0.0 の画面にはありません。ツールバーに「チャットをエクスポート」ボタンがある場合は、先にチャットを選び、そのボタンから形式と対象を選択します。

2.0 の書き出し形式
選択肢ライセンス出力
選択中のチャット → HTML認証済みライセンスは不要ブラウザーで読む単一の HTML ファイル
全チャット → HTML認証済みライセンスが必要チャット一覧を含む単一の HTML ファイル
Markdown (ZIP)認証済みライセンスが必要全チャットの Markdown とキャッシュ済みスタンプ

HTML の初期対象は「全チャット」です。一つだけを書き出す場合は「選択中のチャット」を明示的に選んでください。保存して完了を待つと、対応するアプリで結果を開きます。

HTML に埋め込むのはキャッシュにあるスタンプ画像だけです。画像が必要な場合は、該当するスタンプが表示できることを確認してから書き出します。HTML の検索欄はチャット名を絞り込み、全メッセージの本文検索ではありません。会話の表示には JavaScript が必要です。

Markdown ZIP には attachments/stickers/ フォルダと Obsidian 形式の画像参照が含まれます。一般的な Markdown ビューアーではパスや記法の調整が必要な場合があります。画像の欠落や同名チャットのファイルを確認してください。どちらの形式も完全な保存用コピーや LINE 用の読み込みファイルではありません。データベースのバックアップも保管してください。

購入とエクスポートライセンスの認証

確認したコードでは、閲覧、検索、一つのチャットのテキスト保存にエクスポート認証は不要です。テキストの一括書き出しには認証が必要です。2.0 で追加された形式の条件は前章の表を参照してください。購入と認証の成功は別の手順です。

  1. 現在の商品ページで購入方法と納品内容を確認します。
  2. ChatArchive の「ライセンス認証」を開き、この商品向けに提供された対応ライセンスキーを入力します。
  3. オンラインで認証を実行し、結果の状態を確認します。購入明細は非公開で保管します。

確認した両方の版は Lemon Squeezy のライセンスサービスを使います。後の購入リンクが Gumroad を指していても、この点は同じです。Gumroad の購入明細だけではキーの互換性は確認できません。キーが届かない、または拒否される場合は注文番号を添えてサポートへ連絡し、解決のためだけに再購入しないでください。

「ライセンス管理」には、このインストールの認証を解除する操作があります。会話の削除や返金を行う操作ではありません。解除にはサービスからの正常な応答が必要です。

ローカル保存とネットワーク通信

チャットをローカル処理することは、アプリが一切通信しないことを意味しません。確認した実装には次の動作があります。

通信が発生する場面
操作動作
履歴の閲覧と検索保存された会話を Mac 内で処理します。確認した処理経路にチャットをアップロードする送信先はありません。
iCloud からの読み込みmacOS が LINE のバックアップを iCloud からダウンロードする場合があります。Apple Account と iCloud の動作は Apple のサービスが担います。
ライセンスサービス認証ではキーと Mac のコンピュータ名を Lemon Squeezy へ送ります。検証・解除ではキーと認証インスタンスの識別子を送ります。
2.0 のスタンプ取得LINE の CDN への要求にスタンプの識別子が含まれます。サーバーは IP アドレスなど通常の接続情報も受け取ります。
リンクと保存ファイルWeb サイトを開く、購入する、同期フォルダへ保存する操作は外部サービスを使う場合があります。

認証済みのインストールでは、認証または最後の検証成功から 7 日経過後、起動時にライセンスを検証する場合があります。確認した実装では、通信失敗時は以前の認証状態を維持し、無効なライセンスという応答では有料の書き出しが使えなくなる場合があります。これは永続的なオフライン認証の保証ではありません。

ライセンスの認証情報は macOS のキーチェーンに保管します。会話のデータベースは別のローカルファイルです。取り込み済みの本文は取得元を再取得せず読めますが、最初の iCloud ダウンロード、認証、未取得の 2.0 スタンプには接続が必要な場合があります。

バックアップとデータの削除

再読み込みや Mac の移行前に

  1. ChatArchive を完全に終了します。
  2. Finder の「移動」→「フォルダへ移動」で ~/Library/Application Support/ChatArchive/ を開きます。
  3. フォルダ全体を、日付を付けた保護された保存先へコピーします。データベースの付属ファイルとスタンプキャッシュも含めます。
  4. 重要な閲覧用ファイルと元のバックアップも別に保管し、コピーが存在することを確認してから次へ進みます。

これはローカルファイルを保全する手順です。確認した画面に、対応を保証するデータベース復元ウィザードやライブラリ統合機能はありません。移行・復旧では元のコピーを変更せず、版の互換性をサポートへ確認してください。別の Mac ではライセンス認証も別途必要になる場合があります。

ローカル履歴を削除する

確認した画面にチャット単位の削除コマンドはありません。終了して必要なバックアップを取った後、Finder で Application Support 内の ChatArchive フォルダをゴミ箱へ移動できます。ファイルを実際に削除するとローカルの作業用履歴がなくなり、次回起動時には空のライブラリを作成します。書き出しファイルとバックアップコピーは、必要に応じて別に削除します。

アプリ本体の削除だけでは、Application Support のファイルやキーチェーンのライセンスが残る場合があります。ChatArchive のファイルを削除しても、元の LINE の会話や iCloud バックアップは削除しません。ゴミ箱、システムのバックアップ、クラウド上のコピーにはそれぞれ保持の仕組みがあり、この手順は完全消去機能ではありません。
