GitInflow

GitHub Issues Kanban-Client für iOS

GitInflow Benutzerhandbuch

GitInflow ist ein GitHub Issues Kanban-Client für iOS. Dieses Handbuch beschreibt alle Funktionen im Detail.

Erste Schritte

Anmeldung

  1. Starten Sie GitInflow.
  2. Tippen Sie auf „Mit GitHub anmelden" im Anmeldebildschirm.
  3. Authentifizieren Sie sich im Browser oder über die GitHub-App. GitInflow verwendet OAuth und speichert Ihr Passwort niemals.

Repositories auswählen

  1. Gehen Sie nach der Anmeldung zum Einstellungen-Tab (Zahnrad-Symbol).
  2. Tippen Sie auf Repositories, um sie auszuwählen. Ausgewählte Repos sind mit einem Häkchen markiert.
  3. Sie können gleichzeitig bis zu 5 Repositories auswählen.

Standard-Repository festlegen

Tippen Sie im Einstellungen-Tab auf das Stern-Symbol neben einem Repository, um es als Standard festzulegen. Das Standard-Repository wird verwendet beim:

  • Erstellen einer neuen Issue über die +-Schaltfläche
  • Verwenden der Share-Erweiterung ohne manuell ein Repo zu wählen

Kanban-Tabs

GitInflow organisiert Issues in vier Statusspalten, jede durch einen Tab dargestellt:

TabBeschreibungGitHub-Label
BacklogIssues ohne Status-Label — der Eingang für neue Aufgaben(kein Label)
ReadySortierte Issues, bereit zum Startenstatus:ready
In ProgressAktiv bearbeitete Issuesstatus:inProgress
DoneAbgeschlossene Issues — werden auf GitHub automatisch geschlossenstatus:done

Status ändern

Es gibt vier Möglichkeiten, den Status einer Issue zu ändern:

Nach links wischen — Hinzufügen / Vorwärts

Wischen Sie eine Issue-Karte nach links, um Schnellaktionen anzuzeigen:

  • Label — Label-Auswahl öffnen
  • Meilenstein — Meilenstein-Auswahl öffnen
  • Vorwärts — Issue zum nächsten Status verschieben (z.B. Backlog → Ready → In Progress → Done)

Nach rechts wischen — Zurück / Kommentieren

Wischen Sie eine Issue-Karte nach rechts, um anzuzeigen:

  • Zurück — Issue zum vorherigen Status zurückverschieben
  • Kommentieren — Kommentar-Sheet öffnen

Kontextmenü (Langes Drücken)

Drücken Sie lange auf eine Issue-Karte, um ein Kontextmenü mit allen verfügbaren Statusoptionen zu öffnen.

Issue-Detail-Schaltflächen

Tippen Sie auf eine Issue, um den Issue-Detail-Bildschirm zu öffnen. Statusänderungs-Schaltflächen befinden sich unten.

Suche

Jeder Kanban-Tab hat oben eine Suchleiste. Tippen Sie darauf, um Issues im aktuellen Tab nach Schlüsselwort zu filtern.

  • Die Suche entspricht Issue-Titeln.
  • Die Suche ist lokal und aktualisiert sich in Echtzeit.
  • Leeren der Suchleiste stellt die vollständige Liste wieder her.

Repository-Filter

Bei zwei oder mehr ausgewählten Repositories erscheint eine Reihe von Filter-Chips unterhalb der Tab-Leiste.

  • Tippen Sie auf einen Chip, um nur Issues aus diesem Repository anzuzeigen.
  • Tippen Sie auf Alle, um Issues aus allen ausgewählten Repositories anzuzeigen.

Issues erstellen

  1. Navigieren Sie zu einem beliebigen Kanban-Tab (die +-Schaltfläche ist immer oben rechts sichtbar).
  2. Tippen Sie auf +.
  3. Geben Sie einen Titel (erforderlich) und optional einen Text ein.
  4. Tippen Sie auf Senden, um die Issue auf GitHub zu erstellen.

Issue-Detail

Tippen Sie auf eine Issue-Karte, um den Detail-Bildschirm zu öffnen. Er zeigt: Titel, Status-Badge, Labels, Meilenstein, Text, Kommentare und Statusänderungs-Schaltflächen.

Labels & Meilensteine

Label über Wischen hinzufügen

  1. Wischen Sie eine Issue-Karte nach links.
  2. Tippen Sie auf die Aktion Label.
  3. Ein Auswahl-Sheet erscheint. Tippen Sie auf ein Label, um es ein- oder auszuschalten.
  4. Tippen Sie auf Fertig, um anzuwenden.
Hinweis: Labels und Meilensteine werden von GitHub abgerufen. Erstellen Sie sie zuerst auf GitHub.com.

Kommentare

  1. Wischen Sie eine Issue-Karte nach rechts.
  2. Tippen Sie auf Kommentieren.
  3. Tippen Sie Ihren Kommentar ein und tippen Sie auf Senden.

Share-Erweiterung

Die Share-Erweiterung ermöglicht das Erstellen oder Aktualisieren von GitHub Issues direkt aus jeder App heraus.

  1. Tippen Sie in einer App auf den Teilen-Button.
  2. Scrollen Sie und tippen Sie auf GitInflow Share. Wenn nicht sichtbar, tippen Sie auf Mehr und aktivieren Sie es.

Pull-Requests-Tab

Tippen Sie auf den PRs-Tab, um alle offenen Pull Requests aus Ihren ausgewählten Repositories zu sehen. PRs sind in GitInflow schreibgeschützt.

Widget

GitInflow bietet ein Startbildschirm-Widget, das Ihre Issue-Anzahl auf einen Blick zeigt (Klein: In Progress; Mittel: alle vier Status).

Benachrichtigungen

GitInflow kann lokale Benachrichtigungen senden, wenn neue Issues in Ihren ausgewählten Repositories erscheinen.

Einstellungen

Öffnen Sie den Einstellungen-Tab (Zahnrad-Symbol), um Repositories zu verwalten, ein Standard-Repository festzulegen und sich abzumelden.

Fehlerbehandlung

Wenn GitInflow Issues aus einem Repository nicht laden kann, erscheint ein roter Fehlerbanner. Tippen Sie auf Wiederholen, um erneut zu versuchen.

FAQ

Wie viele Repositories kann ich auswählen?

Bis zu 5 Repositories gleichzeitig.

Was bewirkt der „Done"-Status auf GitHub?

GitInflow fügt das Label status:done hinzu und schließt die Issue auf GitHub.

Kann ich GitInflow mit privaten Repositories verwenden?

Ja. GitInflow verwendet Ihr GitHub OAuth-Token, das Zugriff auf alle autorisierten Repositories hat.
