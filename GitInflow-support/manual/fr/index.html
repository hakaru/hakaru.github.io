GitInflow

Client Kanban GitHub Issues pour iOS

Manuel utilisateur GitInflow

GitInflow est un client kanban GitHub Issues pour iOS. Ce manuel couvre toutes les fonctionnalités en détail.

Démarrage

Connexion

  1. Lancez GitInflow.
  2. Appuyez sur « Se connecter avec GitHub » sur l'écran de connexion.
  3. Authentifiez-vous dans le navigateur ou via l'application GitHub. GitInflow utilise OAuth et ne stocke jamais votre mot de passe.

Sélectionner des dépôts

  1. Après la connexion, accédez à l'onglet Paramètres (icône d'engrenage).
  2. Appuyez sur les dépôts pour les sélectionner. Les dépôts sélectionnés sont cochés.
  3. Vous pouvez sélectionner jusqu'à 5 dépôts simultanément.

Définir un dépôt par défaut

Dans l'onglet Paramètres, appuyez sur l'icône étoile à côté d'un dépôt pour le définir par défaut. Le dépôt par défaut est utilisé lors de :

  • La création d'une nouvelle issue via le bouton +
  • L'utilisation de l'Extension de partage sans choisir manuellement un dépôt

Onglets Kanban

GitInflow organise les issues en quatre colonnes de statut, chacune représentée par un onglet :

OngletDescriptionÉtiquette GitHub
BacklogIssues sans étiquette de statut — la boîte de réception des nouveaux travaux(aucune étiquette)
ReadyIssues triées et prêtes à démarrerstatus:ready
In ProgressIssues en cours de traitementstatus:inProgress
DoneIssues terminées — fermées automatiquement sur GitHubstatus:done

Appuyez sur un onglet pour y accéder. Chaque onglet affiche uniquement les issues correspondant à ce statut dans vos dépôts sélectionnés.

Changer le statut

Il existe quatre façons de changer le statut d'une issue :

Glisser à gauche — Ajouter / Avancer

Glissez une carte d'issue vers la gauche pour révéler des actions rapides :

  • Étiquette — Ouvrir le sélecteur d'étiquettes
  • Jalon — Ouvrir le sélecteur de jalons
  • Avancer — Déplacer l'issue vers le statut suivant (ex. Backlog → Ready → In Progress → Done)

Glisser à droite — Reculer / Commenter

Glissez une carte d'issue vers la droite pour révéler :

  • Reculer — Déplacer l'issue vers le statut précédent (ex. In Progress → Ready)
  • Commenter — Ouvrir une feuille de commentaire pour ajouter un commentaire à l'issue

Menu contextuel (appui long)

Appuyez longuement sur une carte d'issue pour ouvrir un menu contextuel avec toutes les options de statut disponibles. Cela permet d'accéder directement à n'importe quel statut sans glisser plusieurs fois.

Boutons de détail de l'issue

Appuyez sur une issue pour ouvrir l'écran Détail de l'issue. Les boutons de changement de statut sont affichés en bas de l'écran — appuyez sur Avancer ou Reculer pour déplacer l'issue.

Recherche

Chaque onglet kanban dispose d'une barre de recherche en haut. Appuyez dessus pour filtrer les issues de l'onglet actuel par mot-clé.

  • La recherche correspond aux titres des issues.
  • La recherche est locale (pas de requête réseau supplémentaire) et se met à jour en temps réel.
  • Effacer la barre de recherche restaure la liste complète.

Filtre de dépôt

Lorsque vous avez deux dépôts ou plus sélectionnés dans Paramètres, une rangée de puces de filtre apparaît sous la barre d'onglets sur l'écran kanban.

  • Appuyez sur une puce pour afficher les issues de ce dépôt uniquement.
  • Appuyez sur Tous (la puce la plus à gauche) pour afficher les issues de tous les dépôts sélectionnés.
  • Le filtre s'applique à l'onglet actuel uniquement ; changer d'onglet conserve votre sélection de filtre.

Créer des issues

  1. Accédez à n'importe quel onglet kanban (le bouton + est toujours visible en haut à droite).
  2. Appuyez sur +.
  3. Si vous avez plusieurs dépôts sélectionnés, un sélecteur de dépôt apparaît — choisissez le dépôt cible. Si vous avez un dépôt par défaut défini, il est présélectionné.
  4. Entrez un titre (obligatoire) et un corps optionnel.
  5. Appuyez sur Soumettre pour créer l'issue sur GitHub. La nouvelle issue apparaît dans l'onglet Backlog.

Détail de l'issue

Appuyez sur une carte d'issue pour ouvrir son écran de détail. L'écran de détail affiche :

  • Titre — Titre et numéro de l'issue
  • Badge de statut — Statut kanban actuel (Backlog / Ready / In Progress / Done)
  • Étiquettes — Toutes les étiquettes assignées à l'issue
  • Jalon — Jalon assigné, le cas échéant
  • Corps — Description de l'issue (rendue en texte brut)
  • Commentaires — Tous les commentaires existants par ordre chronologique
  • Boutons de changement de statut — Boutons Avancer et Reculer en bas

Étiquettes & Jalons

Ajouter une étiquette via le glissement

  1. Glissez une carte d'issue vers la gauche.
  2. Appuyez sur l'action Étiquette.
  3. Une feuille de sélection apparaît avec toutes les étiquettes du dépôt de l'issue.
  4. Appuyez sur une étiquette pour l'activer ou la désactiver.
  5. Appuyez sur Terminé pour appliquer.

Ajouter un jalon via le glissement

  1. Glissez une carte d'issue vers la gauche.
  2. Appuyez sur l'action Jalon.
  3. Une feuille de sélection apparaît avec tous les jalons ouverts du dépôt.
  4. Appuyez sur un jalon pour l'assigner, ou appuyez sur Aucun pour supprimer le jalon actuel.
  5. Appuyez sur Terminé pour appliquer.
Remarque : Les étiquettes et jalons sont récupérés depuis GitHub. Créez-les sur GitHub.com ou l'application GitHub d'abord.

Commentaires

Ajouter un commentaire via le glissement

  1. Glissez une carte d'issue vers la droite.
  2. Appuyez sur l'action Commenter.
  3. Une feuille de commentaire apparaît. Tapez votre commentaire.
  4. Appuyez sur Publier pour soumettre.

Ajouter un commentaire depuis le détail de l'issue

  1. Appuyez sur une issue pour ouvrir l'écran de détail.
  2. Faites défiler jusqu'en bas de la liste des commentaires.
  3. Appuyez sur le champ Ajouter un commentaire.
  4. Tapez votre commentaire et appuyez sur Publier.

Extension de partage

L'extension de partage vous permet de créer ou mettre à jour des GitHub Issues directement depuis n'importe quelle application — navigateur, Notes, Safari, etc.

Activer l'extension de partage

  1. Dans n'importe quelle application, appuyez sur le bouton Partager (boîte avec flèche).
  2. Faites défiler la feuille de partage et appuyez sur GitInflow Share. Si elle n'apparaît pas, appuyez sur Plus et activez-la.

Mode Nouvelle issue

  1. Dans l'extension de partage, sélectionnez Nouvelle issue dans le sélecteur de mode.
  2. Choisissez un dépôt (votre dépôt par défaut est présélectionné).
  3. Le contenu partagé (URL, texte sélectionné, image) est pré-rempli dans le corps.
  4. Modifiez le titre et le corps si nécessaire.
  5. Appuyez sur Créer pour publier l'issue.

Mode Ajouter à une issue existante

  1. Sélectionnez Ajouter à une issue existante dans le sélecteur de mode.
  2. Choisissez un dépôt.
  3. Une liste des issues ouvertes dans ce dépôt apparaît — appuyez sur l'issue à laquelle vous souhaitez ajouter.
  4. Le contenu partagé est pré-rempli comme commentaire.
  5. Appuyez sur Publier pour ajouter le commentaire.

Onglet Pull Requests

Appuyez sur l'onglet PRs pour voir toutes les pull requests ouvertes de vos dépôts sélectionnés.

  • Chaque ligne affiche le titre de la PR, le dépôt et l'auteur.
  • Appuyez sur une PR pour l'ouvrir dans Safari (GitHub web).
  • Utilisez les puces de filtre de dépôt pour filtrer par dépôt.
Les pull requests sont en lecture seule dans GitInflow. Utilisez GitHub.com ou l'application GitHub pour réviser et fusionner les PRs.

Widget

GitInflow fournit un widget d'écran d'accueil qui affiche le nombre de vos issues en un coup d'œil.

TailleContenu
PetitNombre d'issues In Progress
MoyenNombre pour les quatre statuts : Backlog / Ready / In Progress / Done

Ajouter le widget

  1. Appuyez longuement sur une zone vide de votre écran d'accueil.
  2. Appuyez sur + (coin supérieur gauche) pour ouvrir la galerie de widgets.
  3. Recherchez GitInflow.
  4. Sélectionnez Petit ou Moyen.
  5. Appuyez sur Ajouter un widget et positionnez-le.

Notifications

GitInflow peut envoyer des notifications locales lorsque de nouvelles issues apparaissent dans vos dépôts sélectionnés.

  • Les notifications sont générées lors de l'actualisation des données d'issues (en premier plan ou en arrière-plan).
  • Les nouvelles issues absentes lors de l'actualisation précédente déclenchent une notification.
  • Appuyez sur une notification pour ouvrir GitInflow directement sur l'issue concernée.

Activer les notifications

iOS vous invitera à autoriser les notifications au premier lancement. Si vous avez refusé, allez dans Réglages iOS → GitInflow → Notifications et activez-les.

Paramètres

Ouvrez l'onglet Paramètres (icône d'engrenage) pour gérer :

Sélection des dépôts

  • Appuyez sur n'importe quel dépôt dans la liste pour le sélectionner ou désélectionner.
  • Une coche indique un dépôt sélectionné.
  • Vous pouvez sélectionner jusqu'à 5 dépôts.

Dépôt par défaut

  • Appuyez sur l'icône étoile à côté d'un dépôt pour le définir par défaut.
  • L'étoile devient pleine/jaune sur le défaut sélectionné.
  • Un seul défaut peut être défini à la fois.

Déconnexion

Appuyez sur Déconnexion (en bas des Paramètres) pour vous déconnecter de votre compte GitHub. Toutes les données mises en cache localement sont effacées lors de la déconnexion.

Gestion des erreurs

Bannière d'erreur de dépôt

Si GitInflow ne peut pas charger les issues d'un dépôt (ex. erreur réseau, accès révoqué), une bannière d'erreur rouge apparaît en haut de l'écran kanban indiquant quel dépôt a échoué.

Bouton Réessayer

Appuyez sur le bouton Réessayer dans la bannière d'erreur pour re-récupérer immédiatement les issues du dépôt en erreur.

FAQ

Combien de dépôts puis-je sélectionner ?

Jusqu'à 5 dépôts peuvent être sélectionnés simultanément dans Paramètres.

Que fait le statut « Done » sur GitHub ?

Lorsque vous déplacez une issue vers Done, GitInflow ajoute l'étiquette status:done et ferme l'issue sur GitHub. La ramener à tout autre statut rouvre l'issue.

Puis-je utiliser GitInflow avec des dépôts privés ?

Oui. GitInflow utilise votre token OAuth GitHub qui a accès à tous les dépôts que vous avez autorisés lors de la connexion.

L'extension de partage n'apparaît pas. Que faire ?

Dans la feuille de partage, appuyez sur Plus, trouvez GitInflow Share dans la liste et activez-le.

Pourquoi mes étiquettes ou jalons n'apparaissent pas ?

Les étiquettes et jalons sont récupérés depuis GitHub. Assurez-vous que le dépôt en possède et que vous avez accès au réseau.

Pourquoi le widget ne se met pas à jour ?

Les widgets iOS se rafraîchissent selon un planning géré par le système. Ouvrez GitInflow au moins une fois pour déclencher une actualisation des données.

J'ai déplacé accidentellement une issue vers Done. Comment annuler ?

Glissez la carte d'issue vers la droite dans l'onglet Done et appuyez sur Reculer, ou appuyez longuement sur la carte et sélectionnez un statut dans le menu contextuel.
