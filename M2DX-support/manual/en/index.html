Version, requirements and scope

M2DX is a six-operator, 32-algorithm FM synthesizer. Play it on its screen keyboard, connect a MIDI keyboard, or load its AUv3 instrument in a compatible host. M2DX-Core is the Swift library that generates the FM sound; the app adds its interface, presets, MIDI connections and effects.

  • This manual covers the published M2DX 1.7.14 (build 40), using M2DX-Core 1.25.0 and MIDI2Kit 1.0.19. Later development changes are outside this guide.
  • The current App Store listing specifies iPhone, iOS 18 or later. It also lists compatibility with Apple Silicon Macs running macOS 15 or later, while stating that the iPhone app has not been verified on macOS. Do not assume a native Mac edition or an iPad-optimized edition from that compatibility listing.
  • The manual has 11 languages. The published app lists English as its interface language. Control names such as LIVE and SAVE remain in English here.
  • The app and AUv3 instrument are free to download. M2DX Pro is an optional one-time purchase; check its current price in the app. The available Pro functions differ between standalone and AUv3.

The descriptions below distinguish a capability of the MIDI standard, a function inside the library, and a feature that can actually be reached through the released app. These are different levels of support.

Play your first sound

  1. Open M2DX and select LIVE. Keep the device or audio-interface volume moderate.
  2. Show the on-screen keyboard with its keyboard toggle if it is hidden, then tap a key. External MIDI hardware is optional.
  3. Tap a preset in LIVE. Use current bank name to choose another bank, then tap a sound in that bank.
  4. Change the keyboard octave to reach a different register. The screen keyboard starts with velocity 100; use Settings → Velocity for its curve or an external keyboard to vary playing strength.
  5. Open FX to shape the sound, or EDIT to change the synthesis parameters. Save an edited voice before choosing another one.

For a USB keyboard, connect a compatible interface or adapter and check MIDI reception. For a Bluetooth MIDI keyboard, open Settings → MIDI → Bluetooth MIDI and connect there. Bluetooth MIDI transmits performance data; it is separate from Bluetooth audio, which can add noticeable monitoring delay.

If no sound is heard, test a factory patch on the screen keyboard first. This separates an audio-output problem from a controller-connection problem. See Troubleshooting.

Banks, custom voices and saving

A bank groups voices; selecting a voice replaces the current single FM patch. Factory sounds, imported SysEx banks and your saved CUSTOM voices are separate collections. Use the LIVE bank picker to reach all of them.

Save a voice you edited

  1. Select a starting voice and open EDIT.
  2. Make your changes and tap SAVE.
  3. Enter a name and finish saving. Each save creates a new custom voice, even if another voice has the same name. SAVE is not an overwrite command.
  4. To recall it, return to LIVE, tap the current bank name, choose CUSTOM at the end of the bank list, and tap the saved voice.

Saving clears the unsaved-edit indicator, but does not automatically move the current bank or preset selection to CUSTOM. CUSTOM is hidden until it contains at least one saved voice. CUSTOM stores the voice, controller routing/EG mode, Mono/Poly and portamento on/off/time, plus internal FX. It does not store an entire host project, an external AU chain, engine/divisor/DAC options, MIDI Learn mappings or a TX816 stack. Use REVERT to return to the edit baseline, or INIT to initialize the voice after confirmation; INIT does not reset every app setting.

Delete a custom voice

In the CUSTOM bank, long-press the voice, choose Delete, and confirm. This removes the stored entry; the currently loaded sound can remain audible. Keep a separate copy of any source SysEx files you need to reimport.

Import DX7 SysEx voices

A .syx file is a MIDI System Exclusive data file. DX7 voice data describes operators, envelopes and common patch settings; it does not contain recorded audio. The released importer accepts a 4104-byte DX7 32-voice bulk bank. It checks the header, 7-bit data and checksum; it does not accept a single-voice dump.

  1. Save the source .syx file in a location available through the Files picker.
  2. Open Settings → Custom SysEx Banks → Import .syx Bank…, select the file, then tap Done.
  3. Return to LIVE → current bank name and select the imported bank, then choose a voice.
  4. If needed, edit that voice and use SAVE to create a separate CUSTOM copy.

Use a 32-voice bank when exchanging files with M2DX. A single-voice dump must first be placed in a compatible bank using a librarian such as Dexed. A filename ending in .syx does not establish compatibility: other synthesizers’ SysEx formats and extended DX-family data may differ. A malformed file or unsupported message cannot be made compatible just by renaming it. Unzip an archive before selecting its bank file. Importing the same filename adds a numbered copy instead of overwriting the existing bank. Swipe an imported bank’s row in Settings to delete the app’s copy; the original Files document is not removed. The public interface has no voice or bank Export command.

DX7 SysEx does not carry M2DX effects, Pro layering, engine settings or Dexed plug-in state. For a controlled sound comparison, start with the same DX7 patch data and disable added processing. See Matching sounds with Dexed.

How six-operator FM makes a sound

An operator is an oscillator with its own level and envelope. A carrier reaches the audio output; a modulator changes another operator’s phase, creating additional frequency components. DX-style FM is implemented as phase modulation: signals are not simply multiplied together.

OP 2
Modulator→OP 1
Carrier→Audio output

The algorithm chooses how the six operators connect. Some are long modulation chains; others have several carriers in parallel. Changing the algorithm can change the sound drastically even when every operator value stays the same.

  • Raise a carrier’s output level to change that branch’s audible level.
  • Raise a modulator’s output level to increase modulation depth, usually adding brightness or a more complex spectrum.
  • Use an integer frequency ratio such as 1:1 or 2:1 for a harmonically related starting point. Non-integer relationships often produce bell-like or metallic tones.
  • Feedback returns an operator signal into its feedback path. More feedback can add harmonics or a rougher texture.

A useful first exercise is to choose an algorithm with a simple two-operator branch, lower the other carriers, set both operators to a 1:1 ratio, and slowly raise the modulator level. Then shorten only the modulator’s envelope: the sound becomes bright at the beginning and mellower as it continues.

Operator frequency, level and scaling

In EDIT, select an operator and change one parameter at a time while repeating the same note. Operator numbers identify their positions in the algorithm; an operator is not always a carrier just because of its number.

The current editor exposes Level 0–99, VEL 0–7, AMS 0–3, KRS 0–7 and Feedback 0–7. Feedback is enabled only for the feedback operator in the selected algorithm. Operator envelopes, pitch envelope and LFO

Each operator has four envelope rates R1–R4 and four levels L1–L4. At note-on the envelope progresses through its first three target levels; the sustained stage uses L3. Note-off starts the final transition toward L4. Rates control transition speed; they are not durations in milliseconds, and the distance between levels also affects the time.

For a short electric-piano attack, let the modulator start strongly and fall quickly to a lower L3, while the carrier decays more slowly. For a pad, slow the carrier’s initial rise and avoid an overly sharp modulator onset. If a sound keeps ringing after release, inspect R4/L4, sustain, and reverb separately.

The pitch envelope changes the voice’s pitch over time. It uses its own rates and levels; it is not another amplitude envelope. Start with small pitch changes because strong settings can dominate the patch.

The shared LFO supplies periodic pitch or amplitude movement. Waveform, speed, delay and depth shape that movement. Pitch modulation produces vibrato; amplitude modulation produces tremolo, with the operator’s sensitivity determining how strongly it responds. Key sync controls whether an oscillator or LFO restarts with a note; it can affect repeated-note attacks and comparisons.

Keep FM Engine, Mark I Depth and the controller EG MODE fixed while editing. The same saved DX7 numbers can respond differently when the engine’s modulation scaling or controller EG bias behavior changes; see Engine settings.

Drag the four points in the envelope graph to adjust the corresponding levels and rates; higher R values are faster. The pitch-envelope center level is 50. The numeric readouts below the graph display the values rather than opening text-entry fields. LFO Speed, Delay, PMD and AMD span 0–99, with PMS 0–7 and TRI, SAW▼, SAW▲, SQR, SIN or S&H waveforms.

Velocity, controllers, mono and portamento

The LIVE keyboard sends a fixed starting velocity of 100; the current interface has no VEL slider. Settings → Velocity → Velocity Curve offers Linear, Soft, Hard and DX7 Keyboard 1-100. Soft raises intermediate values, Hard lowers them, and the DX7 option limits values above 100. Test velocity-sensitive patches with an external keyboard as well.

LIVE TRANSPOSE shifts the entire performance by ±24 semitones; tap its value to reset to zero. It is separate from EDIT’s patch transpose, and the two offsets add together. EDIT also offers PB Range (1–12 semitones) and Tuning (±100 cents). PB Range returns to 2 when loading a voice; master tuning is retained.

Route expressive controllers

EDIT → CONTROLLERS has WHEEL (CC1), FOOT (CC4), BREATH (CC2) and A.TOUCH (channel pressure). Each has Pitch, Amp and EG amounts from 0–99. Pitch drives vibrato, Amp drives amplitude modulation, and EG applies envelope bias. This routing is different from assigning a physical knob with MIDI Learn.

  • EG MODE DX7: applies to operators with AMS enabled. A resting controller can attenuate those operators, and raising it opens them toward their normal level. EG amount zero disables this bias. Check this mode if a breath-controlled patch is silent before you blow.
  • EG MODE BOOST: increases operator levels with controller input, including modulators, so brightness as well as loudness can change. It preserves the earlier M2DX behavior.

Play one note at a time

In Settings → Performance, choose Poly or Mono. Portamento and its time are also available in EDIT. In Mono, Fingered glides between overlapping notes; Full-time also glides between separated notes. Glissando moves in semitone steps. Mono uses one voice from the first enabled part; it does not play an eight-part layer or Voice Stack as a polyphonic stack.

Save a current CUSTOM voice to retain its Mono/Poly, portamento on/off/time and controller routing/EG mode. Global velocity curve, tuning, PB range and the separate Mono Portamento/Glissando settings are not stored in that voice save. For an AUv3 session, save the host project as well.

When loading factory or imported voices, standalone retains the current controller routing, while AUv3 resets it to the DX7 defaults. A current-format CUSTOM voice restores its saved routing. Save a CUSTOM copy when you need repeatable breath or other controller settings.

Change a few parameters at a time. More drive, compressor input or maximizer input can increase apparent loudness as well as change tone. AUv3 uses the standard FX chain even after buying Pro.

TX816 layers, Voice Stack and Pro

TX816 LAYER combines different patches and/or unison copies. It is distinct from the experimental Voice Stack multiplier in standalone Settings.

  1. Open LAYER and choose a PARTS × UNISON partition: 8×1, 4×2, 2×4 or 1×8. OFF returns to single-patch operation. Pro is required to enable layering.
  2. Tap each part’s patch name in LAYER MIXER and choose a patch. Adjust LVL (−24 to +6 dB), PAN, and optionally RND for a new random pan per note.
  3. Set DETUNE (0–12 cents) and Even or Random distribution. Play from an external MIDI source or AU host; this page has no screen keyboard.
  4. Open FX to keep playing the stack while adjusting the shared effects. Returning to LIVE or EDIT switches to the single patch.
  5. Use the save icon, SAVE STACK and a name to create a new stack. The … menu opens MANAGE STACKS, with FACTORY DEMOS and MY STACKS. Saved user stacks can be deleted there.

A stack embeds its component DX7 patch data, partition, detune, part levels/pan and shared internal FX. Choosing a CUSTOM voice for a part uses its DX7 patch, not every custom performance and FX setting as an independent part configuration. Effects process the combined signal; there is no separate FX chain per layer. Saved MY STACKS are not guaranteed to synchronize between standalone and AUv3.

Use external AU effects in the app

With Pro in standalone, open AU → ADD EFFECT in one of the four slots. Choose an installed audio effect from the Audio Units list. The chain runs after M2DX’s internal effects.

  • BYP bypasses a slot; the controls icon opens the effect’s interface when one is available; × removes it.
  • NOT INSTALLED means the saved plug-in cannot be found. LOAD FAILED indicates a load failure; use its retry control after checking installation.
  • The app restores this chain separately from CUSTOM voices and saved TX816 stacks. Do not expect changing a voice to replace the external chain.

This page hosts effects, not additional instrument plug-ins. Its visibility can depend on the app’s feature configuration. When M2DX itself is loaded as AUv3, add other effects in the host rather than looking for this AU page.

Use M2DX inside an AUv3 host

  1. Install and open the main app once. In a compatible host, add M2DX FM Synthesizer as an instrument.
  2. Route the host’s keyboard, MIDI track or external MIDI input to it, and enable monitoring as required by that host.
  3. Select a voice and edit using LIVE, EDIT, LAYER or FX. The plug-in has four tabs; its bottom gear opens Performance, not the standalone app’s general Settings.
  4. Import .syx banks in the main app. Reopen the AU interface or bring it forward to refresh the shared library. CUSTOM and imported banks share storage within the same installation.
  5. Save the host project to retain instance settings. Use EDIT → SAVE separately when you want a reusable CUSTOM voice.

The host manages audio rate, buffer size, MIDI routing and automation. The main app’s MIDI Input, Channel and Bluetooth settings do not configure the AU instance. Use the host’s parameter automation or MIDI mapping; the visible in-app MIDI Learn controls are not wired to AU MIDI reception in this release.

The host can expose FM Engine and Mark I Depth parameters. The AU engine initializes at ÷5, while its parameter declares ÷1 and the standalone default is ÷1. The host can reapply its state; explicitly match the value when comparing them. Standard FX and optional Pro TX816 layers work in AUv3. Pro preamp/compressor/reverb, standalone external-AU hosting, Vintage DAC and Voice Stack are not equivalent AU features.

Version 1.7.14 scales the interface in larger host windows. Program Changes can be consumed by a host for its own patch selection, so confirm that they actually reach the M2DX instance. AU MIDI support also depends on which event format the host supplies; see the implementation table below.

M2DX-Core: from a note to audio

M2DX-Core is the Swift 6 synthesis library, separate from the app and its plug-in wrapper. It implements operators, the 32 algorithms, envelopes, pitch and scaling, voice allocation, patch structures and synthesis-side controller handling. The app provides connections, MIDI-CI/PE, interface, purchases, storage and effects.

MIDI / parameters→ Event queue / snapshot→ M2DX-Core voices→ Mix→ App FX→ Audio output

Fixed-point operators and lookup tables

The main operator calculations use Int32 Q24-style phase and signal values. One phase cycle corresponds to 224 units, and wider Int64 intermediate products can be shifted back to the desired scale. Q24 is an internal numerical representation, not an audio-file format or proof that the entire app is integer-only.

Modern uses a sine table with 1024 intervals and linear interpolation; an exponential table converts logarithmic levels to amplitude. Table lookup and interpolation avoid calculating a full sine or exponential expression for every operator sample. Tables are prepared during initialization rather than generated by the compiler. Frequency conversion, controller normalization, LFO, mixing and the app’s effects also use floating-point operations.

Envelopes and stable rendering

Operator envelopes use an internal Q16 representation, updated in blocks, with gain or attenuation interpolated by the synthesis kernel. The engine works in internal chunks of up to 64 samples. Parameter snapshots and an event queue move changes into rendering; preallocated storage and atomic communication are designed to avoid waiting and allocation in the audio callback.

This internal block size does not make incoming MIDI events sample-accurate. In the released standalone path, source timestamps are not used to schedule note events at individual sample offsets. The AU path processes its event list before rendering rather than splitting the buffer at each event time. Audible timing depends on the host, operating system, buffer and connection as well.

Voices and layers

The normal single-patch configuration has a 16-voice budget with oversampling off, unison 1 and Voice Stack 1. Layer/unison/stack copies each consume processing voices; oversampling changes the budget. The library’s larger internal buffer limits are not a guarantee that thousands of independent keyboard notes will play reliably on a phone. Reduce multipliers and effects when the device cannot keep up.

Source: SynthEngine, DX7Voice, sine table, envelope.

Modern, Mark I, Depth and Vintage DAC

Modern uses the integer sine-and-gain kernel associated with the MSFA-style reference model. It is not a separate “Clean Float32” engine. Mark I uses a logarithmic sine/exponential model informed by public descriptions of the original OPS behavior: it folds phase into a quadrant, combines logarithmic attenuation, then converts back to amplitude. It is not a cycle-accurate simulation of every original chip operation.

What Mark I Depth actually changes

Mark I Depth is a divisor for forward modulation, not the output volume, bit depth or envelope speed. ÷1 keeps the modulation strong; a larger divisor weakens the signal fed into the next operator’s phase and usually makes the sound less bright. Carrier output and the feedback signal are not directly divided by this control.

In standalone, use Settings → Audio → Mark I Depth: ÷1–÷16 in 0.1 steps, free to adjust. The current default is Mark I at ÷1.0 with DAC off; a previously saved preference can override the default. Pro adds the Modern/Mark I choice and Vintage DAC option. Switching engines stops currently sounding notes, so change it between phrases.

AU initial-value caveat: the host parameter declares a Depth default of 1, but the AU engine initialization sets 5. The host may reapply its parameter state. The final value on first opening was not tested for every host; set it explicitly when matching sounds. Engine/Depth control setters exist, but render-event automation does not handle these controls in the same way as ordinary voice parameters, so verify the host’s behavior rather than assuming every automation path works.

Vintage DAC and oversampling

The optional Vintage 12-bit DAC applies amplitude-dependent companding and quantization to raw Mark I voice output. It is a separate tone-shaping stage, not just a final-output bit crusher and not a MIDI-resolution setting. Standalone Audio also provides Oversampling OFF/HQ/Low. Compare by ear and monitor CPU load; oversampling is not an automatic improvement for every patch and changes available voice resources.

What the reference tests establish

Core contains sample comparisons of the Modern integer calculations against an Apache-licensed MSFA/Dexed reference. Some tests inject reference phase increments to isolate the kernel; production pitch calculation is a separate path. Mark I tests compare against an independently written C twin, including a ÷8 test condition that differs from the app’s ÷1 default. These tests do not prove that every final app output, Dexed setting or physical DX7 recording is bit-identical.

Licenses: M2DX-Core is Apache-2.0, MIDI2Kit is MIT, and the M2DX app has its own proprietary license. The test-only C reference is not the production Swift library. See Core LICENSE, NOTICE, Mark I kernel and comparison-test conditions.

MIDI 2.0 explained: messages and resolution

MIDI carries performance instructions, such as which note to play, how strongly to play it, and how a pedal moves. The receiving synthesizer creates the audio. MIDI 2.0 does not change the audio sample rate or audio-file bit depth.

UMP (Universal MIDI Packet) is a packet format that can carry both MIDI 1.0 and MIDI 2.0 messages. Seeing UMP on a connection is not, by itself, proof of high-resolution MIDI 2.0 Channel Voice data. CoreMIDI can translate between protocols according to the receiver’s API and selected protocol. Apple’s CoreMIDI explanation.

What higher resolution can and cannot do

Finer control values can reduce stepping when the sender, connection and sound engine preserve and use them. Converting a 7-bit keyboard value into a 16-bit field does not create extra detail that the keyboard never measured. A DX7 parameter whose range is 0–99 still has that discrete range after receiving a high-resolution controller. MIDI bit scaling and resolution.

Groups, channels and expression per note

Applicable UMP messages have up to 16 groups with 16 channels per group. These addresses do not guarantee 256 instrument parts or 256 voices in an app. MIDI 2.0 also defines per-note pitch and controllers, useful for bending one held note without bending the rest of a chord. M2DX’s actual routing limits appear in the next chapter.

MIDI 1.0 already has polyphonic key pressure. Traditional MIDI 1.0 MPE obtains further per-note control by assigning notes to separate channels; native MIDI 2.0 per-note messages use a different representation. Modern MPE Profiles also cover MIDI 2.0, so “MPE” and “MIDI 2.0” are not mutually exclusive labels. MPE specification; MIDI-CI MPE Profile.

Why a 16-bit velocity is not 65,536 different DX7 responses

The protocol value reaches Core in 16-bit form, but the DX7 velocity-sensitivity calculation shifts it down to 7 bits and indexes a 64-entry table. The operator’s sensitivity setting further determines the result. FX controls reduce values to 0–127; operator output levels use the DX range 0–99. Channel controls also pass through normalization. Receiving a large integer does not mean every integer produces a distinct audible state.

Channel, group and timing limits

Standalone Settings offers Omni or channels 1–16 as an input filter. After filtering, group/channel identity is not maintained as independent instrument parts. Channel pitch bend acts on the synth as a whole, not on a separate MPE member voice. Core has additional per-note APIs, but their existence does not overcome the released transport and routing gaps.

MIDI 2.0 does not make this release sample-accurate or eliminate latency. Source timestamps and host sample offsets are not fully used for per-event scheduling. Do not infer timing guarantees from the 64-sample internal processing chunks.

Source: transport dispatch, AU event handler, velocity scaling and Core expression handling.

MIDI-CI, Profiles and Property Exchange

MIDI-CI lets devices exchange capability information. Profiles define common behavior for a particular musical use; they are not sound presets. Property Exchange (PE) lets an implementer expose named resources such as device information, program lists or control descriptions. A PE-capable connection does not guarantee that every DAW can automatically edit every instrument parameter. MIDI Association overview; Profiles.

The old MIDI-CI Protocol Negotiation procedure was deprecated in the 2023 revision. Current general explanations should distinguish capability exchange from UMP protocol selection. M2DX’s shipped compatibility behavior is not a claim to implement every current Profile or specification option. Official 2023 revision notes.

Connect controllers and use MIDI Learn

In standalone Settings → MIDI, choose All Sources or a specific MIDI Input, and Omni (All) or a channel from 1–16. Connected MIDI Devices and Refresh Devices help confirm the connection. Use Bluetooth MIDI for a BLE MIDI controller. Check the header’s activity dot while playing.

  1. Long-press a supported FX slider without moving it for about half a second.
  2. Choose Learn CC in its MIDI Learn menu.
  3. While LEARN flashes, move the hardware knob or fader. The first received CC is assigned and learning stops.
  4. Long-press the same slider again to cancel a pending learn. Use Settings → MIDI Learn → Reset All Mappings to restore mappings.

Supported targets include MIX/basic FX sliders, selected Pro continuous controls, LAYER DETUNE and part LVL. LAYER PAN, every FM editor control, and all effect switches/choices are not automatically learnable. One CC has one learned target; a new assignment replaces its earlier learned target. Original standard functions such as sustain may still respond, so avoid repurposing those CCs accidentally.

Select voices with Bank Select and Program Change

MIDI values are zero-based. A controller displaying programs 1–128 may send wire values 0–127. The CUSTOM card’s B16 PC0 means bank MSB 16 and transmitted Program Change 0, not necessarily the controller’s displayed program number.

CUSTOM numbers remain stable when other voices are deleted; they are not renumbered to match list positions. An unassigned CUSTOM number leaves the current sound unchanged. For standalone bank selection, send the bank messages each time: the bank is consumed by the next matching-channel PC rather than assumed to remain selected indefinitely.

AUv3 follows its factory/CUSTOM selection path and parks the active layer. A host may consume PC before it reaches M2DX. AU program loading is also deferred to the UI/control side, so a Note On at the same instant as PC can still use the previous sound. Choose by the job

  • M2DX advantage: an immediate mobile instrument, screen keyboard, built-in creative effects and optional layering. Its limitations include the smaller platform/plug-in range, differences between standalone and AUv3, and incomplete MIDI expression paths.
  • Dexed advantage: desktop DAW integration, cartridge organization, hardware editing and alternate tuning. It needs a desktop environment, and its reviewed internal processing is less of a complete effects chain.
  • These are workflow conclusions from the documented features, not an audio-quality ranking. No controlled listening test or identical-render test between these two releases was performed for this manual.

For Dexed’s editing workflow, see the official overview and MIDI CC context-menu implementation.

Move sounds and compare them fairly

  1. In Dexed, export a compatible 32-voice DX7 cartridge as .syx. Import that file in M2DX and select the same voice.
  2. Use single-patch mode. Disable M2DX layers, Voice Stack and added effects; remove host effects and neutralize Dexed’s output filtering and gain shaping.
  3. Match the sample rate, tuning, transpose, engine mode, feedback, operator values, envelopes, key sync and velocity input as closely as possible.
  4. Check M2DX’s Mark I divisor, EG mode and DAC setting separately. Their defaults and scaling need not match Dexed’s engine of the same name.
  5. Send the same note sequence, note lengths, velocities, sustain and controller values. Compare single notes before dense chords that might trigger voice stealing.
  6. Match perceived output level, then compare the attack, sustained spectrum and release. If they differ, isolate one parameter or processing stage at a time.

A shared patch format and related fixed-point synthesis techniques do not guarantee identical output samples. Differences may come from engine behavior, controller conversion, envelope mode, gain, effects or routing. Core’s reference tests cover specified conditions; they do not certify every patch, device, sample rate or setting as identical to Dexed or a physical DX7.
