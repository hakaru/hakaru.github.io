対象バージョン・動作環境・このマニュアルの範囲

M2DXは、6オペレーター・32アルゴリズムのFMシンセサイザーです。画面鍵盤やMIDIキーボードで演奏でき、対応ホストではAUv3音源として使えます。FM音を生成するSwiftライブラリーがM2DX-Coreで、アプリが画面、プリセット、MIDI接続、エフェクトを提供します。

  • 対象は公開版M2DX 1.7.14（build 40）、組み込まれているM2DX-Core 1.25.0とMIDI2Kit 1.0.19です。その後の開発中の変更は含みません。
  • 現在のApp Store掲載情報はiPhone、iOS 18以降を対象としています。macOS 15以降のApple Silicon Macとの互換性も掲載されていますが、iPhoneアプリでありmacOSでは未検証と明記されています。この互換性表示から、ネイティブMac版やiPad向け最適化版があるとは判断できません。
  • マニュアルは11言語対応です。公開アプリのUI言語は英語と掲載されています。本書でもLIVEやSAVEなど、実際の操作名は英語のまま示します。
  • アプリとAUv3音源は無料でダウンロードできます。M2DX Proは任意の買い切り購入です。現在の価格はアプリ内で確認してください。単体アプリとAUv3では利用できるPro機能が異なります。

本書では、MIDI規格に存在する機能、ライブラリー内部の機能、公開アプリから実際に利用できる機能を区別します。それぞれの「対応」は同じ意味ではありません。

まず音を出す

  1. M2DXを開き、LIVEを選びます。端末やオーディオインターフェースの音量は控えめにします。
  2. 画面鍵盤が隠れていれば鍵盤表示の切替で表示し、キーをタップします。外部MIDI機器は必須ではありません。
  3. LIVEのプリセットをタップします。現在のバンク名をタップすると別のバンクを選べます。その中から音色をタップしてください。
  4. 鍵盤のオクターブを変えると別の音域を弾けます。画面鍵盤の入力ベロシティは100です。Settings → Velocityでカーブを変えるか、外部鍵盤で打鍵の強さを変えて試します。
  5. FXで音を加工し、EDITで音源の設定を変更できます。別の音色を選ぶ前に、残したい編集を保存します。

USB鍵盤は対応するインターフェースやアダプターを接続し、MIDI受信を確認します。Bluetooth MIDI鍵盤はSettings → MIDI → Bluetooth MIDIから接続します。Bluetooth MIDIが送るのは演奏データです。音声を送るBluetoothオーディオとは別で、Bluetoothオーディオには演奏時に気になる遅延が生じることがあります。

音が出ない場合は、まず工場音色を画面鍵盤で試します。音声出力の問題と、外部コントローラーの接続の問題を切り分けられます。トラブルシューティングも参照してください。

バンク・CUSTOM・音色の保存

バンクは音色のまとまりです。音色を選ぶと現在の単体FMパッチが置き換わります。工場音色、取り込んだSysExバンク、自分で保存したCUSTOMは別の一覧です。LIVEのバンク選択からそれぞれに移動できます。

編集した音色を保存する

  1. 元にする音色を選び、EDITを開きます。
  2. 編集してSAVEをタップします。
  3. 名前を入力し、保存します。同じ名前の音色があっても、毎回新しいCUSTOM音色が作られます。SAVEは上書き操作ではありません。
  4. 呼び出すときはLIVEへ戻り、現在のバンク名をタップして、一覧末尾のCUSTOMから保存音色を選びます。

保存すると未保存編集の印は消えますが、現在のバンクや選択音色が自動的にCUSTOMへ切り替わるわけではありません。CUSTOMは保存音色が1件以上あると表示されます。CUSTOMには音色、コントローラールーティング／EG MODE、Mono/Poly、Portamentoのオン／オフと時間、内蔵FXが保存されます。ホストプロジェクト全体、外部AUチェーン、エンジン／除数／DAC設定、MIDI Learn割当、TX816スタックは含みません。REVERTは編集の基準状態へ戻し、INITは確認後に音色を初期化します。INITですべてのアプリ設定がリセットされるわけではありません。

CUSTOM音色を削除する

CUSTOMバンクで音色を長押しし、Deleteを選んで確認します。保存済みの項目は削除されますが、読み込まれている音はそのまま鳴る場合があります。再取込が必要なSysEx元ファイルは別に保管してください。

DX7 SysEx音色を取り込む

.syxはMIDI System Exclusiveデータのファイルです。DX7音色データにはオペレーターやエンベロープなどの設定が入り、録音された音声は入りません。公開版のインポーターが受け付けるのは4104バイトのDX7 32音色バルクバンクです。ヘッダー、7bitデータ、チェックサムを検証し、単音色ダンプは受け付けません。

  1. 元の.syxファイルを、Filesの書類選択から開ける場所に保存します。
  2. Settings → Custom SysEx Banks → Import .syx Bank…からファイルを選び、Doneをタップします。
  3. LIVEの現在のバンク名をタップして取込バンクを選び、その中の音色を選択します。
  4. 必要なら編集し、SAVEで別のCUSTOM音色として保存します。

M2DXとの受け渡しには32音色バンクを使います。単音色ダンプはDexedなどのライブラリアンで対応バンクに組み込んでから取り込んでください。拡張子が.syxでも、別のシンセサイザーやDX系の拡張形式は互換とは限りません。破損データや未対応メッセージを名前の変更だけで対応形式にはできません。ZIPは解凍して中のバンクを選びます。同名ファイルの再取込では既存バンクを上書きせず、番号付きのコピーが追加されます。取込バンクはSettingsの行をスワイプして削除できますが、Files側の元ファイルは削除されません。公開UIには音色／バンクのExport操作はありません。

DX7 SysExにはM2DXのFX、Proレイヤー、エンジン設定、Dexedプラグイン全体の状態は含まれません。音を比較するときは同じDX7パッチを使い、追加処理を切って始めます。Dexedと音を比較するも参照してください。

6オペレーターFMの仕組み

オペレーターは、専用のレベルとエンベロープを持つ発振器です。キャリアは音声出力に届き、モジュレーターは別のオペレーターの位相を変えて周波数成分を増やします。DX系のFMは位相変調として実装されており、単純に波形同士を掛け算する方式ではありません。

OP 2
モジュレーター→OP 1
キャリア→音声出力

アルゴリズムは6個の接続方法です。長い変調の連鎖もあれば、複数キャリアを並列に鳴らすものもあります。各数値が同じでも、接続を変えると音は大きく変化します。

  • キャリアの出力レベルを上げると、その枝の音量が変わります。
  • モジュレーターの出力レベルを上げると変調が深くなり、一般に明るさやスペクトルの複雑さが増します。
  • 1:1や2:1などの整数比は調和した音の出発点になります。非整数の関係はベルや金属的な音に向いています。
  • フィードバックは信号の一部を戻します。増やすと倍音やざらつきが加わります。

最初の練習では、2オペレーターの単純な枝があるアルゴリズムを選び、ほかのキャリアを下げ、両方を1:1にしてモジュレーターのレベルをゆっくり上げます。次にモジュレーターのエンベロープだけを短くすると、出だしは明るく、その後は柔らかくなる音を作れます。

オペレーターの周波数・レベル・スケーリング

EDITでオペレーターを選び、同じ音を繰り返しながら1項目ずつ変えます。番号はアルゴリズム内の位置を示すもので、特定の番号が常にキャリアとは限りません。

主なオペレーター設定
設定聴きどころ
Ratio / Fixed、Coarse / FineRatioは鍵盤の音程に追従します。Fixedは絶対周波数を指定し、通常の鍵盤追従と異なる変調に使えます。Coarseで大きく、Fineで細かく調整します。
Output Levelキャリアなら音量、モジュレーターなら変調の深さを変えます。DXの数値は単純な線形の音量パーセントではありません。
Detune音程を少しずらします。コーラスを足す前に、並列キャリア間のわずかな差を試すと揺れが得られます。
Velocity sensitivity打鍵の強さがこのオペレーターのレベルへどれだけ影響するかを決めます。モジュレーターでは主に明るさ、キャリアでは音量も変わります。

1.7.14のWAVEの制限：編集画面には波形の選択肢がありますが、出荷Coreの設定処理は発振波形を変更しません。公開エンジンはサイン波を使います。この版のWAVEで8波形音源やDX7II音源へ変わるとは考えないでください。

編集範囲はLevel 0–99、VEL 0–7、AMS 0–3、KRS 0–7、Feedback 0–7です。Feedbackは選択アルゴリズムのフィードバック対象OPでのみ操作できます。大きなRatioスライダーは0.50–16.00ですが、CRS（0–31）とFIN（0–99）ではその範囲を超える比も扱います。CRS 0は×0.5です。Detuneは−50～+50 cents。OP1–OP6は編集対象の選択で、ソロ／ミュートではありません。

OPエンベロープ・ピッチEG・LFO

各オペレーターには4つのレートR1–R4とレベルL1–L4があります。ノートオンから最初の3つの目標レベルへ進み、キーを保持している間はL3を保ちます。ノートオフでL4への最後の遷移が始まります。レートは移動の速さで、ミリ秒指定ではありません。レベル間の距離も時間に影響します。

短いエレピのアタックを作るなら、モジュレーターを強く始めて低いL3へ早く落とし、キャリアをゆっくり減衰させます。パッドならキャリアの立ち上がりを遅くし、モジュレーターの出だしを鋭くしすぎないようにします。離鍵後も音が続く場合はR4/L4、サステイン、リバーブを別々に確認します。

ピッチエンベロープは音程を時間とともに変化させます。専用のレートとレベルを使い、振幅エンベロープとは別です。大きく変えると音全体を支配するので、まず小さな変化から試します。

共通のLFOは周期的な音程や振幅の変化を作ります。波形、速度、遅延、深さで動きを調整します。音程変調はビブラート、振幅変調はトレモロになり、各OPの感度も反応量に関わります。Key syncは発音時に発振器やLFOを再スタートするかを決め、反復音のアタックや音の比較に影響します。

編集中はFM Engine、Mark I Depth、コントローラーのEG MODEを固定しておくと比較しやすくなります。同じDX7の保存値でも、変調のスケールやコントローラーのEG Bias動作を変えると反応が変わります。エンジン設定を参照してください。

グラフの4点をドラッグして、対応するレベルとレートを変えます。Rが大きいほど速くなります。ピッチEGの中心レベルは50です。グラフ下の数値は表示用で、タップして文字入力する欄ではありません。LFOのSpeed、Delay、PMD、AMDは0–99、PMSは0–7、波形はTRI、SAW▼、SAW▲、SQR、SIN、S&Hです。

ベロシティ・コントローラー・Mono・ポルタメント

LIVEの画面鍵盤が送る基本ベロシティは100で、現行UIにVELスライダーはありません。Settings → Velocity → Velocity CurveにはLinear、Soft、Hard、DX7 Keyboard 1-100があります。Softは中間値を上げ、Hardは下げ、DX7は100を超える値を制限します。ベロシティに反応する音色は外部鍵盤でも試してください。

LIVEのTRANSPOSEは演奏全体を±24半音移動し、数値をタップすると0に戻ります。EDITの音色内Transposeとは別で、両方が加算されます。EDITのPB Rangeは1–12半音、Tuningは±100 cents。音色を読み込むとPB Rangeは2へ戻りますが、マスターチューニングは維持されます。

演奏コントローラーを音へ割り当てる

EDIT → CONTROLLERSにはWHEEL（CC1）、FOOT（CC4）、BREATH（CC2）、A.TOUCH（チャンネルプレッシャー）があります。それぞれPitch、Amp、EGを0–99で設定します。Pitchはビブラート、Ampは振幅変調、EGはエンベロープバイアスです。物理ノブのCCをMIDI Learnで割り当てる操作とは別です。

  • EG MODE DX7：AMSを設定したOPへ作用します。コントローラーが休止中はそのOPを減衰させ、値を上げると通常のレベルまで開きます。EG量0ならこのBiasは無効です。ブレス音色で吹く前に音が出ないときは、この設定を確認します。
  • EG MODE BOOST：モジュレーターを含むOPレベルを操作量に応じて持ち上げ、音量だけでなく明るさも変えます。以前のM2DXの動作を維持するモードです。

単音で演奏する

Settings → PerformanceでPolyまたはMonoを選びます。Portamentoと時間はEDITにもあります。MonoのFingeredは重ね押しの間だけ、Full-timeは離して弾いた音の間も滑らかにつなぎます。Glissandoは半音単位で移動します。Monoは最初の有効パートの1ボイスを使い、8パートのレイヤーやVoice Stack全体を重ねて鳴らす動作にはなりません。

現行CUSTOMへ保存すると、Mono/Poly、Portamentoのオン／オフと時間、コントローラールーティング／EG MODEを保持できます。グローバルなVelocity Curve、Tuning、PB Range、別項目のMono Portamento／Glissandoはその音色保存に含まれません。AUv3の制作ではホストプロジェクトも保存してください。

工場音色や取込音色への切替時、単体アプリは現在のコントローラールーティングを維持し、AUv3はDX7既定値へ戻します。現行形式のCUSTOMは保存されたルーティングを復元します。ブレスなどの設定を確実に呼び出したい場合はCUSTOMに保存してください。

エフェクトで音を整える

通常の内蔵信号経路は次の順です。

FM→ EQ→ Drive→ Chorus→ Reverb→ Stereo→ Maximizer
FX画面の操作
セクション設定と使いどころ
MIXVOLUME、EXPRESSION、MOD WHEEL。Expressionが低いと、音色が正常でも音が出ないことがあります。MOD WHEELの作用はコントローラールーティングに従います。
EQ / DRIVELOW/HIGHは音のバランス、OVERDRIVEは飽和感を変えます。音量をそろえて比較してください。
CHORUSSPEED/DEPTHで揺れと広がりを加えます。音程がぼやけすぎる場合はDepthを下げます。
REVERBTIME/LEVELは空間の長さと量です。ドライ音を離鍵しても長い残響は続きます。
STEREOWIDTHでステレオの広がりを変えます。広がりを重視した音はモノ再生でも確認します。
MAXIMIZERINPUT/CEILINGは最後のダイナミクス段への入力と出力上限です。それ以前の各段の音量調整が不要になるわけではありません。

FX画面の並び順と信号の処理順は同じとは限りません。CUSTOMには内蔵FX設定と、使用しているPro FX設定が保存されます。外部AUチェーンは別保存です。

Proの単体アプリではP73 → EQ → Drive → Chorus → 1176 → DigitalReverb → Stereo → Maximizerとなります。PREAMPはP73のGain、Output、ハイパス、トーン設定。COMPは1176のInput/Output、Attack/Release、Ratio、Mixとゲインリダクション表示です。REVERB PROはHALL'78、HALL'86、PLATE、NONLIN、LO-FI'86、HALL'99を選び、Predelay、Size、Damping、Low Cut、Mod、Widthを調整します。通常のREVERBのTIME/LEVELも長さと量に使います。

少数の項目から調整してください。Drive、コンプレッサー入力、マキシマイザー入力を上げると、音色と同時に聴感音量も変わります。AUv3はPro購入後も標準FXチェーンを使います。

TX816レイヤー・Voice Stack・Pro

TX816 LAYERは異なる音色やユニゾンコピーを重ねます。単体Settingsの実験機能Voice Stackの倍率とは別の機能です。

  1. LAYERを開き、PARTS × UNISONを8×1、4×2、2×4、1×8から選びます。OFFは単体動作に戻します。レイヤーを有効にするにはProが必要です。
  2. LAYER MIXERの各パート名をタップして音色を選び、LVL（−24～+6 dB）、PANを調整します。RNDを使うとノートごとにランダムなパンになります。
  3. DETUNE（0–12 cents）、EvenまたはRandomの分布を選びます。この画面に鍵盤はないので、外部MIDIまたはAUホストから演奏します。
  4. FXへ移動するとスタックを保ったまま共通FXを調整できます。LIVEやEDITへ戻ると単体音色に切り替わります。
  5. 保存アイコンからSAVE STACKを開き、名前を付けて新規保存します。…のMANAGE STACKSにはFACTORY DEMOSとMY STACKSがあり、ユーザースタックの削除もできます。

スタックには各パートのDX7パッチ、Partition、Detune、レベル／パン、共通内蔵FXが入ります。パートにCUSTOMを選んでも、そのDX7パッチを使うだけで、CUSTOM側の演奏設定やFXのすべてを各パートへ独立して再現するわけではありません。FXは合成後の音を処理し、レイヤーごとに別のチェーンはありません。MY STACKSの単体アプリ／AUv3間の自動同期も保証されません。

単体アプリで外部AUエフェクトを使う

Proの単体アプリでAU → ADD EFFECTを開き、4スロットのいずれかへインストール済みAudio Unitエフェクトを追加します。このチェーンは内蔵FXの後を処理します。

  • BYPはそのスロットをバイパスし、操作アイコンは対応するエフェクトUIを開き、×は削除します。
  • NOT INSTALLEDは保存されたプラグインが見つからない状態、LOAD FAILEDは読込失敗です。インストールを確認して再試行します。
  • このチェーンはCUSTOM音色やTX816スタックとは別に復元されます。音色を変えても外部チェーンが置き換わるとは限りません。

ここで読み込むのはエフェクトで、追加の音源ではありません。タブの表示はアプリの機能設定にも依存します。M2DXをAUv3として使うときは、このAU画面ではなくホスト側に別のエフェクトを追加してください。

AUv3ホスト内でM2DXを使う

  1. 本体をインストールして一度開き、対応ホストでM2DX FM Synthesizerを音源として追加します。
  2. ホストの鍵盤、MIDIトラック、外部MIDI入力をM2DXへ送り、そのホストに必要なモニター設定を行います。
  3. LIVE、EDIT、LAYER、FXで音色を選択・編集します。プラグインは4タブで、下部の歯車はPerformanceです。本体の一般Settingsではありません。
  4. .syxバンクは本体から取り込みます。AU画面を開き直すか前面へ戻すと共有ライブラリーを再読込します。CUSTOMと取込バンクは同じインストール内で共有されます。
  5. インスタンスの状態を残すにはホストプロジェクトを保存します。再利用用のCUSTOM音色は別にEDIT → SAVEで保存します。

サンプルレート、バッファー、MIDI経路、自動化はホストが管理します。本体のMIDI Input、Channel、Bluetooth設定でAUインスタンスを設定するわけではありません。割当にはホストのパラメーター自動化／MIDIマッピングを使います。この版では、画面にあるアプリ内MIDI LearnはAUのMIDI受信へ接続されていません。

ホストからFM EngineとMark I Depthを操作できます。AU音源内部は÷5で初期化されますが、パラメーターの既定値と単体アプリの既定値は÷1です。ホストが自身の状態を再適用する場合もあるため、比較時は明示的にそろえてください。標準FXとProのTX816レイヤーは利用できます。Proのプリアンプ／コンプレッサー／リバーブ、外部AUホスト機能、Vintage DAC、Voice Stackが単体版と同じ形で使えるわけではありません。

1.7.14は大きなホストウィンドウでUIを拡大します。Program Changeがホスト自身のパッチ切替に使われることもあるため、M2DXまで届くか確認してください。対応するMIDI機能はホストが渡すイベント形式にも依存します。後述の実装対応表を参照してください。

M2DX-Core：ノート情報から音声になるまで

M2DX-CoreはアプリやAUラッパーから独立したSwift 6の音源ライブラリーです。オペレーター、32アルゴリズム、エンベロープ、音程とスケーリング、ボイス割当、パッチ構造、音源側のコントローラー処理を担当します。接続、MIDI-CI/PE、UI、購入、保存、エフェクトはアプリ側です。

MIDI／パラメーター→ イベントキュー／スナップショット→ M2DX-Coreのボイス→ ミックス→ アプリFX→ 音声出力

固定小数点演算と参照テーブル

主なOP演算はInt32 Q24系の位相・信号値を使います。1周期を224として表し、積はInt64の中間値から必要なスケールへ戻せます。Q24は内部の数値表現で、音声ファイル形式でも、アプリ全体が整数だけで動くという意味でもありません。

Modernは1024区間のサイン波テーブルと線形補間を使い、指数テーブルで対数レベルを振幅へ変換します。OPの毎サンプルで完全なsinやexp計算を繰り返す代わりに、表参照と補間を使います。テーブルはコンパイラーが生成するのではなく初期化時に準備します。周波数変換、コントローラー正規化、LFO、ミックス、アプリのFXには浮動小数点も使われます。

エンベロープと安定した音声処理

OPエンベロープは内部Q16表現を使ってブロックごとに更新され、カーネルがゲインや減衰を補間します。音源内部の処理単位は最大64サンプルです。パラメータースナップショットとイベントキューで変更を渡し、事前確保した領域やアトミック通信でオーディオコールバック内の待機・メモリー確保を避ける設計です。

この内部ブロックサイズが、入力MIDIをサンプル単位の時刻どおりに処理するという意味ではありません。公開単体版では受信タイムスタンプによる個々のサンプル位置への発音予約を使っていません。AUも各イベント時刻でバッファーを分割するのではなく、音声処理前にイベント列を処理します。実際のタイミングはホスト、OS、バッファー、接続にも依存します。

ボイス数とレイヤー

通常の単体音色はOversampling OFF、Unison 1、Voice Stack 1で16ボイスの予算を持ちます。レイヤー／ユニゾン／スタックのコピーはそれぞれボイスを消費し、オーバーサンプリングでも予算が変わります。ライブラリー内部の大きなバッファー上限は、電話で何千もの独立した鍵盤音を安定して鳴らせる保証ではありません。処理が追いつかないときは倍率やFXを減らしてください。

出典：SynthEngine、DX7Voice、サイン波テーブル、エンベロープ。

Modern・Mark I・Depth・Vintage DAC

ModernはMSFA系参照モデルに対応する整数のサイン波・ゲイン演算です。別の「Clean Float32」音源ではありません。Mark Iは公開されたOPSの動作資料に基づく対数サイン／指数モデルで、位相を象限へ折り返し、対数減衰を組み合わせてから振幅へ戻します。実機チップの全動作をサイクル精度で再現するものではありません。

Mark I Depthは何を変えるのか

Mark I Depthは前向きの変調量に使う除数で、出力音量、ビット深度、EG速度ではありません。÷1は強い変調を保ち、大きな除数ほど次のOPの位相へ入る信号を弱め、一般に暗い音になります。キャリア出力とフィードバック信号を直接この値で割るわけではありません。

単体アプリのSettings → Audio → Mark I Depthは÷1–÷16、0.1刻みで無料です。現行の既定はMark I、÷1.0、DAC OFFですが、以前に保存した設定が優先する場合があります。ProではModern/Mark Iの切替とVintage DACが加わります。エンジン切替は発音中のノートを止めるので、フレーズの間に行ってください。

AUの初期値に関する注意：ホストパラメーター上のDepth既定値は1、音源内部の初期化は5です。ホストがパラメーター状態を再適用する場合があり、初回の最終状態をすべてのホストで実測したわけではありません。比較時は明示的に設定します。Engine/Depthの設定処理はありますが、音声処理イベント経由の自動化は通常の音色パラメーターと同じ扱いではありません。すべての自動化経路で動くと仮定せず、使用ホストで確認してください。

Vintage DACとオーバーサンプリング

任意のVintage 12-bit DACはMark Iの各ボイスの生出力へ、振幅依存のコンパンディングと量子化を適用します。最終段の単純なビットクラッシャーではなく、MIDI解像度の設定でもありません。単体AudioにはOversampling OFF/HQ/Lowもあります。耳とCPU負荷で比較してください。すべての音色で自動的に良くなるわけではなく、発音資源の配分も変わります。

参照テストで確認する範囲

CoreにはModernの整数計算をApacheライセンスのMSFA/Dexed参照実装とサンプル単位で比較するテストがあります。一部はカーネルを分離して調べるため参照側の位相増分を注入し、本番の音程計算とは経路が違います。Mark Iは独立して作ったC版との比較で、アプリ既定の÷1とは違う÷8の試験条件も含みます。これらはアプリの最終出力、Dexedの全設定、実機DX7の録音がすべてビット一致する証明ではありません。

MIDI 2.0の仕組み：メッセージと解像度

MIDIは、どの音をどの強さで弾くか、ペダルをどう動かすか、といった演奏指示を送ります。音声は受信側の音源が作ります。MIDI 2.0で音声のサンプルレートやファイルのビット深度が変わるわけではありません。

UMP（Universal MIDI Packet）はMIDI 1.0とMIDI 2.0の両方を運べるパケット形式です。UMP接続というだけでは、高解像度のMIDI 2.0 Channel Voiceを受けている証拠になりません。CoreMIDIは受信APIや選択されたプロトコルに応じて形式を変換できます。AppleのCoreMIDI解説。

高解像度でできること・できないこと

送信機器、接続、音源が細かい値を維持して利用すれば、変化の段差を減らせます。ただし、7bit鍵盤の値を16bitの箱へ変換しても、鍵盤が測定していない情報は増えません。0–99のDX7パラメーターは、高解像度コントローラーを受けてもその離散範囲を持ちます。MIDIのビットスケーリングと解像度。

Group・Channel・ノート別の表現

対象となるUMPメッセージは最大16グループ、各16チャンネルのアドレスを持ちます。これだけでアプリに256パートや256ボイスがあるとは限りません。MIDI 2.0にはノート別ピッチやコントローラーもあり、和音中の1音だけを曲げるような表現に使えます。M2DXの実際の経路の制限は次章で説明します。

MIDI 1.0にもポリフォニック・キープレッシャーはあります。従来のMIDI 1.0 MPEはノートを別々のチャンネルへ分けてノート別表現を実現し、MIDI 2.0のネイティブなノート別メッセージとは表現方法が異なります。現在のMPE ProfileはMIDI 2.0も扱うため、MPEとMIDI 2.0は互いに排他的な名称ではありません。MPE仕様、MIDI-CI MPE Profile。

16bitベロシティでも65,536段階のDX7応答とは限らない理由

規格上の値は16bitでCoreまで届きますが、DX7のベロシティ感度計算は7bitへシフトし、64要素のテーブルを参照します。OPの感度設定によっても結果が変わります。FXは0–127、OP出力レベルはDXの0–99へ変換され、チャンネル制御も正規化されます。大きな整数を受信することと、そのすべてが別の可聴状態になることは同じではありません。

チャンネル・グループ・時刻の制限

単体SettingsのOmni／1–16は入力フィルターです。フィルター後にGroup/Channelを独立したパートとして維持するわけではありません。チャンネルPitch BendはMPEの特定ボイスではなく音源全体へ作用します。Coreには追加のノート別APIもありますが、それだけで公開トランスポートやルーティングの不足を補えるわけではありません。

MIDI 2.0だからこの版がサンプル精度で動いたり、遅延が消えたりすることはありません。受信タイムスタンプやホストのサンプルオフセットは、イベントごとの時刻指定に十分活用されていません。内部64サンプル単位の処理からタイミング保証を推定しないでください。

出典：トランスポートの振り分け、AUイベント処理、ベロシティスケーリング、Coreの表現処理。

MIDI-CI・Profiles・Property Exchange

MIDI-CIは機器同士で能力情報を交換する仕組みです。Profilesは用途ごとの共通動作を定めるもので、音色プリセットではありません。Property Exchange（PE）は機器情報、音色一覧、操作項目などを名前付きリソースとして公開する仕組みです。PE接続があるだけで、どのDAWからでも全パラメーターを自動編集できるとは限りません。MIDI Associationの概要、Profiles。

旧MIDI-CI Protocol Negotiation手順は2023年改定で非推奨になりました。現在の説明では能力交換とUMP側のプロトコル選択を分けます。M2DXの互換処理も、現行の全Profileや全仕様項目を実装したという意味ではありません。2023年改定の公式説明。

MIDI接続とMIDI Learn

単体のSettings → MIDIでAll Sourcesまたは特定のMIDI Input、Omni (All)または1–16のチャンネルを選びます。Connected MIDI DevicesとRefresh Devicesで接続を確認し、BLE鍵盤にはBluetooth MIDIを使います。演奏しながらヘッダーの受信点も確認します。

  1. 対応するFXスライダーを動かさず、約0.5秒長押しします。
  2. MIDI LearnメニューのLearn CCを選びます。
  3. LEARNの点滅中に機器のノブ／フェーダーを動かします。最初に受信したCCを割り当て、学習を終了します。
  4. 待機を中止するには同じスライダーをもう一度長押しします。割当を戻すにはSettings → MIDI Learn → Reset All Mappingsを使います。

対象はMIX／基本FXスライダー、一部のPro連続値、LAYER DETUNE、パートLVLです。LAYER PAN、FM編集の全項目、FXの全スイッチ／選択肢が学習対象というわけではありません。1つのCCの学習先は1つで、新しい割当は前の学習先を置き換えます。サステインなど元の標準機能は反応することもあるため、不用意に同じCCを流用しないでください。

Bank SelectとProgram Changeで音色を選ぶ

MIDIの値は0始まりです。1–128と表示するコントローラーが送る実値は0–127の場合があります。CUSTOMのB16 PC0はBank MSB 16、送信Program Change 0という意味で、機器画面の表示番号と同じとは限りません。

AUv3は工場／CUSTOM選択の経路を使い、有効なレイヤーを休止します。ホストがPCをM2DXへ渡す前に消費することもあります。またAUの音色読込はUI／制御側へ遅延して渡されるため、PCと同時のNote Onは前の音色で鳴る可能性があります。最初のノートより前に音色を選び、実際のホストで確認してください。

作業に合わせて選ぶ

  • M2DXのメリット：持ち運べる音源、画面鍵盤、内蔵FX、任意のレイヤーをすぐ使えます。一方で対応プラットフォーム／プラグイン形式が限られ、単体とAUv3の差やMIDI表現の未接続部分があります。
  • Dexedのメリット：デスクトップDAW連携、カートリッジ整理、実機編集、特殊な調律に向きます。一方でデスクトップ環境が必要で、確認した内蔵処理だけでは一式のFXチェーンにはなりません。
  • これは仕様から判断した作業上の比較で、音質の順位ではありません。本書のために両版の統制した試聴や同一レンダー試験を実施したわけではありません。

Dexedの編集操作は公式概要とMIDI CCコンテキストメニュー実装も参照してください。

音色を移動し、Dexedと公平に比較する

  1. Dexedから対応する32音色DX7カートリッジを.syxで書き出し、M2DXへ取り込んで同じ音色を選びます。
  2. 単体音色モードを使います。M2DXのレイヤー、Voice Stack、追加FXを無効にし、ホストFXも外して、Dexedの出力フィルターやゲインによる加工をそろえます。
  3. サンプルレート、チューニング、Transpose、エンジン、Feedback、OP値、EG、Key Sync、入力ベロシティをできるだけ一致させます。
  4. M2DXのMark I除数、EG MODE、DACも別に確認します。同じエンジン名でも、Dexedと既定値やスケールが同一とは限りません。
  5. 同じノート列、長さ、ベロシティ、サステイン、コントローラー値を送ります。ボイススティールの影響が出る密な和音の前に単音を比較します。
  6. 聴感音量をそろえ、アタック、持続中の成分、リリースを比べます。差があれば1設定・1処理段ずつ切り分けます。

共通パッチ形式や関連する固定小数点方式だけでは、出力サンプルの一致は保証されません。エンジン、コントローラー変換、EGモード、ゲイン、FX、経路で変わります。Coreの参照テストは指定条件の検証で、全音色・全機器・全サンプルレート・全設定でDexedや実機DX7と同じであることの認定ではありません。
