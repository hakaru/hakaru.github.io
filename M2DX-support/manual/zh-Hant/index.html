版本、系統需求與適用範圍

M2DX 是一款具有六個運算子、32 種演算法的 FM 合成器。您可以使用螢幕鍵盤演奏、連接 MIDI 鍵盤，或在相容的宿主軟體中載入它的 AUv3 樂器。M2DX-Core 是產生 FM 聲音的 Swift 函式庫；App 則提供操作介面、預設音色、MIDI 連線與效果器。

  • 本手冊適用於已發布的 M2DX 1.7.14（組建 40），使用 M2DX-Core 1.25.0 與 MIDI2Kit 1.0.19。後續開發中的變更不在本指南範圍內。
  • 目前的 App Store 頁面標示系統需求為 iPhone、iOS 18 或以上版本。頁面也列出與搭載 Apple Silicon、執行 macOS 15 或以上版本的 Mac 相容，同時註明此 iPhone App 尚未在 macOS 上驗證。這項相容性資訊不代表提供原生 Mac 版本或針對 iPad 最佳化的版本。
  • 本手冊提供 11 種語言。已發布 App 列出的介面語言為英語。因此，LIVE 與 SAVE 等控制項名稱在此仍保留英文。
  • App 與 AUv3 樂器可免費下載。M2DX Pro 為選購的一次性購買項目；請在 App 內確認目前價格。獨立 App 與 AUv3 可使用的 Pro 功能有所不同。

以下說明會區分 MIDI 標準所具備的能力、函式庫內部的功能，以及實際可透過已發布 App 使用的功能。這些是不同層次的支援。

演奏第一個音色

  1. 開啟 M2DX 並選取 LIVE。請將裝置或音訊介面的音量維持在適中程度。
  2. 若螢幕鍵盤未顯示，請使用鍵盤顯示開關將它展開，再輕點琴鍵。不一定需要外接 MIDI 硬體。
  3. 在 LIVE 輕點一個預設音色。輕點目前的音色庫名稱可選取其他音色庫，再輕點該音色庫中的音色。
  4. 調整鍵盤八度以演奏不同音域。螢幕鍵盤的起始力度值為 100；可在 Settings → Velocity 調整力度曲線，或使用外接鍵盤改變演奏力度。
  5. 開啟 FX 調整音色效果，或開啟 EDIT 修改合成參數。選取另一個音色前，請先儲存已編輯的音色。

使用 USB 鍵盤時，請連接相容的介面或轉接器，並確認 MIDI 接收狀態。使用 Bluetooth MIDI 鍵盤時，請開啟 Settings → MIDI → Bluetooth MIDI 並在該處連線。Bluetooth MIDI 傳送的是演奏資料，與藍牙音訊不同；藍牙音訊可能造成明顯的監聽延遲。

如果沒有聲音，請先用螢幕鍵盤測試原廠音色，以區分音訊輸出問題與控制器連線問題。請參閱疑難排解。

音色庫、自訂音色與儲存

音色庫用來整理音色；選取音色會取代目前的單一 FM 音色。原廠音色、匯入的 SysEx 音色庫，以及您儲存的 CUSTOM 音色是不同的集合。可透過 LIVE 的音色庫選單存取全部集合。

儲存編輯過的音色

  1. 選取一個起始音色，然後開啟 EDIT。
  2. 完成修改後輕點 SAVE。
  3. 輸入名稱並完成儲存。每次儲存都會建立一個新的自訂音色，即使已存在同名音色也是如此。SAVE 並不是覆寫指令。
  4. 要重新載入它，請返回 LIVE，輕點目前的音色庫名稱，在音色庫清單末端選取 CUSTOM，再輕點已儲存的音色。

儲存會清除未儲存編輯的指示，但不會自動將目前的音色庫或預設音色選取項目切換到 CUSTOM。CUSTOM 至少包含一個已儲存音色後才會顯示。CUSTOM 會儲存音色、控制器路由／EG 模式、Mono/Poly、滑音的開關與時間，以及內部 FX。它不會儲存整個宿主專案、外部 AU 效果器鏈、引擎／除數／DAC 選項、MIDI Learn 對應或 TX816 疊層。使用 REVERT 可回到編輯基準狀態；使用 INIT 並確認後可初始化音色，但 INIT 不會重設所有 App 設定。

刪除自訂音色

在 CUSTOM 音色庫中長按音色，選取 Delete 並確認。這會移除已儲存的項目；目前載入的聲音仍可能繼續發聲。請另外保留日後需要重新匯入的原始 SysEx 檔案。

匯入 DX7 SysEx 音色

.syx 檔案是 MIDI System Exclusive（系統專屬）資料檔。DX7 音色資料記錄運算子、包絡及音色共用設定，不包含錄製的音訊。已發布版本的匯入功能接受 4104 位元組的 DX7 32 音色整批音色庫。它會檢查標頭、7 位元資料與檢查碼，不接受單一音色傾印。

  1. 將原始 .syx 檔案儲存到「檔案」選擇器可存取的位置。
  2. 開啟 Settings → Custom SysEx Banks → Import .syx Bank…，選取檔案，再輕點 Done。
  3. 返回 LIVE → 目前的音色庫名稱，選取匯入的音色庫，再選取音色。
  4. 需要時可編輯該音色，並使用 SAVE 建立獨立的 CUSTOM 副本。

與 M2DX 交換檔案時，請使用 32 音色庫。單一音色傾印必須先透過 Dexed 等音色管理工具放入相容的音色庫。檔名以 .syx 結尾不代表相容：其他合成器的 SysEx 格式及 DX 系列的擴充資料可能不同。格式錯誤的檔案或不支援的訊息，無法僅靠重新命名變得相容。請先解壓縮封存檔，再選取其中的音色庫檔案。匯入相同檔名會新增帶編號的副本，而非覆寫現有音色庫。在 Settings 滑動匯入音色庫的項目，可刪除 App 內的副本；「檔案」中的原始文件不會被移除。公開介面沒有音色或音色庫的 Export 指令。

DX7 SysEx 不包含 M2DX 效果器、Pro 疊層、引擎設定或 Dexed 外掛狀態。若要在受控條件下比較聲音，請使用相同的 DX7 音色資料，並關閉額外處理。請參閱與 Dexed 比對音色。

六運算子 FM 如何產生聲音

運算子是具有自身電平與包絡的振盪器。載波會到達音訊輸出；調變器則改變另一個運算子的相位，產生額外的頻率成分。DX 類型的 FM 是以相位調變實作，並非單純將訊號相乘。

OP 2
調變器→OP 1
載波→音訊輸出

演算法決定六個運算子的連接方式。有些是長串的調變鏈，有些則有多個並聯載波。即使各運算子的數值完全相同，切換演算法仍可能大幅改變聲音。

  • 提高載波的輸出電平，可改變該分支可聽見的音量。
  • 提高調變器的輸出電平，可增加調變深度，通常會讓聲音更明亮或頻譜更複雜。
  • 使用 1:1 或 2:1 等整數頻率比，可作為具有諧波關係的起點。非整數關係則常產生鐘聲或金屬質感。
  • 回授會將運算子訊號送回其回授路徑。增加回授可增添諧波或更粗糙的質感。

適合初學的練習是：選擇具有簡單雙運算子分支的演算法，降低其他載波的電平，將這兩個運算子都設為 1:1，再慢慢提高調變器電平。接著只縮短調變器的包絡：聲音會在起音時明亮，隨後逐漸柔和。

運算子的頻率、電平與鍵盤縮放

在 EDIT 選取運算子，重複演奏同一個音符，每次只調整一項參數。運算子編號代表它在演算法中的位置；不能僅憑編號判定某個運算子一定是載波。

重要運算子參數
參數聆聽重點
Ratio / Fixed、Coarse / FineRatio 模式會跟隨演奏音高。Fixed 模式設定運算子的絕對頻率，適合製作調變不以一般方式跟隨鍵盤的特殊質感。Coarse 進行較大幅度的調整，Fine 則用於微調。
Output Level改變載波的電平或調變器的深度。DX 的參數刻度不是單純線性的音量百分比。
Detune略微偏移運算子的音高。加入合唱效果前，可先試著讓並聯載波之間出現細微音高差異，製造動態感。
力度靈敏度決定音符力度對此運算子電平的影響程度。調變器的靈敏度主要影響明亮度；載波的靈敏度也會影響音量。
鍵盤電平縮放轉折點、左／右深度與曲線會改變鍵盤各音域的電平。可用來收斂明亮的高音，或加強低音域。
速率縮放讓包絡速度隨琴鍵位置變化。這與電平縮放是不同的設定。
振幅調變靈敏度控制運算子對共用振幅調變訊號的反應程度。LFO 與控制器路由的調變量也必須大於零。

1.7.14 的 WAVE 限制：編輯器提供波形選項，但已出貨 Core 的波形設定函式不會改變振盪器。已發布引擎使用正弦波運算子。請勿依賴 WAVE，將此版本視為具備八種波形或 DX7II 引擎。

目前編輯器提供 Level 0–99、VEL 0–7、AMS 0–3、KRS 0–7 與 Feedback 0–7。Feedback 只會對所選演算法中的回授運算子啟用。主要 Ratio 滑桿範圍為 0.50–16.00，但 CRS（0–31）與 FIN（0–99）可表示超出該滑桿範圍的頻率比；CRS 0 代表 ×0.5。Detune 範圍為 −50 到 +50 音分。OP1–OP6 選擇器用來選取要編輯的運算子，不是獨奏／靜音開關。

運算子包絡、音高包絡與 LFO

每個運算子有四個包絡速率 R1–R4 與四個電平 L1–L4。音符開啟時，包絡依序朝前三個目標電平移動；持續階段使用 L3。音符關閉時，開始最後一段朝 L4 的轉換。速率控制轉換速度，不是以毫秒表示的持續時間；電平之間的距離也會影響所需時間。

要製作短促的電鋼琴起音，可讓調變器以較強的電平開始，快速下降至較低的 L3，同時讓載波緩慢衰減。要製作鋪底音色，可放慢載波最初的上升速度，並避免調變器起音過於尖銳。若放開琴鍵後聲音仍持續，請分別檢查 R4/L4、延音與殘響。

音高包絡會隨時間改變音色的音高。它有自己的速率與電平，並不是另一組振幅包絡。建議先從小幅音高變化開始，因為強烈設定可能主導整個音色。

共用的 LFO 提供週期性的音高或振幅變化。波形、速度、延遲與深度共同決定變化形態。音高調變產生顫音；振幅調變產生震音，而運算子的靈敏度決定其反應強弱。Key sync 控制振盪器或 LFO 是否隨音符重新啟動，可能影響重複音符的起音與比較結果。

編輯時請固定 FM Engine、Mark I Depth 與控制器 EG MODE。若引擎的調變縮放或控制器 EG 偏置行為改變，相同的 DX7 儲存數值也可能產生不同反應；請參閱引擎設定。

拖曳包絡圖上的四個控制點，可調整對應的電平與速率；R 值越高，速度越快。音高包絡的中心電平為 50。圖下方的數值僅用於顯示，不會開啟文字輸入欄位。LFO Speed、Delay、PMD 與 AMD 的範圍為 0–99，PMS 為 0–7，波形選項為 TRI、SAW▼、SAW▲、SQR、SIN 或 S&H。

力度、控制器、單音與滑音

LIVE 鍵盤傳送的固定起始力度值為 100；目前介面沒有 VEL 滑桿。Settings → Velocity → Velocity Curve 提供 Linear、Soft、Hard 與 DX7 Keyboard 1-100。Soft 會提高中間值，Hard 會降低中間值，DX7 選項則限制超過 100 的數值。也請使用外接鍵盤測試對力度敏感的音色。

LIVE 的 TRANSPOSE 可將整段演奏移調 ±24 個半音；輕點其數值可歸零。它與 EDIT 的音色移調不同，兩者的偏移量會相加。EDIT 也提供 PB Range（1–12 個半音）與 Tuning（±100 音分）。載入音色時，PB Range 會恢復為 2；主調音則會保留。

設定表情控制器路由

EDIT → CONTROLLERS 提供 WHEEL（CC1）、FOOT（CC4）、BREATH（CC2）與 A.TOUCH（通道壓力）。每項都有 0–99 的 Pitch、Amp 與 EG 調變量。Pitch 控制顫音，Amp 控制振幅調變，EG 則施加包絡偏置。這種路由與使用 MIDI Learn 指派實體旋鈕不同。

  • EG MODE DX7：作用於已啟用 AMS 的運算子。控制器處於靜止狀態時可能衰減這些運算子，提高控制器值會使它們逐漸回到正常電平。EG 調變量設為零可停用此偏置。若吹管控制音色在吹氣前沒有聲音，請檢查此模式。
  • EG MODE BOOST：隨控制器輸入提高運算子電平，調變器也包含在內，因此明亮度與音量都可能改變。此模式保留了早期 M2DX 的行為。

每次演奏一個音符

在 Settings → Performance 選取 Poly 或 Mono。EDIT 中也可設定滑音及其時間。在 Mono 模式，Fingered 會在重疊的音符之間滑音；Full-time 也會在分開的音符之間滑音。Glissando 則以半音為單位移動。Mono 只使用第一個已啟用聲部的一個發聲單元，不會將八聲部疊層或 Voice Stack 當作複音疊層演奏。

儲存目前的 CUSTOM 音色，可保留其 Mono/Poly、滑音開關／時間及控制器路由／EG 模式。全域力度曲線、調音、PB 範圍，以及獨立的 Mono Portamento/Glissando 設定不會儲存在該音色中。使用 AUv3 工作階段時，也請儲存宿主專案。

載入原廠或匯入音色時，獨立 App 會保留目前的控制器路由，AUv3 則會將它重設為 DX7 預設值。目前格式的 CUSTOM 音色會還原已儲存的路由。若需要可重現的吹管或其他控制器設定，請儲存 CUSTOM 副本。

使用效果器塑造音色

一般內部訊號路徑如下：

FM→ EQ→ Drive→ Chorus→ Reverb→ Stereo→ Maximizer
FX 頁面控制項
區段控制項與實際用途
MIXVOLUME、EXPRESSION 與 MOD WHEEL。即使音色設定正常，過低的表情值也可能使其無聲。MOD WHEEL 依照控制器路由運作。
EQ / DRIVELOW/HIGH 改變音色平衡；OVERDRIVE 加入飽和效果。比較時請使用相近的輸出電平。
CHORUSSPEED 與 DEPTH 增添動態與寬度。若音高變得過於模糊，請降低深度。
REVERBTIME 與 LEVEL 控制空間感及其混合量。原始音符結束後，較長的殘響尾音仍可能持續。
STEREOWIDTH 改變立體聲展寬程度。若寬度是音色的重要部分，請檢查單聲道播放結果。
MAXIMIZERINPUT 與 CEILING 設定送入最後動態處理級的驅動量及其輸出上限。它不能取代前面各級的增益平衡。

FX 區段的畫面排列不代表處理順序。CUSTOM 會儲存內部 FX 設定，包含可用時的 Pro FX 設定；外部 AU 效果器鏈則另外儲存。

在 Pro 獨立 App 中，路徑為 P73 → EQ → Drive → Chorus → 1176 → DigitalReverb → Stereo → Maximizer。PREAMP 提供 P73 增益、輸出、高通與音色控制。COMP 提供 1176 輸入／輸出、起音／釋放、壓縮比與混合量，以及增益衰減表。REVERB PRO 可選擇 HALL'78、HALL'86、PLATE、NONLIN、LO-FI'86 或 HALL'99，並加入預延遲、空間大小、阻尼、低頻截止、調變與寬度。一般殘響的 TIME/LEVEL 仍設定其時間與混合量。

每次只調整少量參數。增加失真驅動量、壓縮器輸入或最大化器輸入，可能同時提高感知音量並改變音色。即使購買 Pro，AUv3 仍使用標準 FX 鏈。

TX816 疊層、Voice Stack 與 Pro

TX816 LAYER 可結合不同音色及／或齊奏副本。它與獨立 App Settings 中實驗性的 Voice Stack 倍增器不同。

  1. 開啟 LAYER，選擇 PARTS × UNISON 分配：8×1、4×2、2×4 或 1×8。OFF 會回到單一音色操作。啟用疊層需要 Pro。
  2. 輕點 LAYER MIXER 中各聲部的音色名稱並選取音色。調整 LVL（−24 到 +6 dB）、PAN，也可啟用 RND，讓每個音符產生新的隨機聲像。
  3. 設定 DETUNE（0–12 音分），以及 Even 或 Random 分布。使用外部 MIDI 來源或 AU 宿主演奏；此頁沒有螢幕鍵盤。
  4. 開啟 FX，可在調整共用效果器時繼續演奏疊層。返回 LIVE 或 EDIT 則會切換為單一音色。
  5. 使用儲存圖示、SAVE STACK 並輸入名稱，可建立新的疊層。… 選單會開啟 MANAGE STACKS，其中包含 FACTORY DEMOS 與 MY STACKS。已儲存的使用者疊層可在此刪除。

疊層會內嵌各組成音色的 DX7 資料、聲部分配、微調、各聲部電平／聲像，以及共用內部 FX。為某聲部選取 CUSTOM 音色時，使用的是它的 DX7 音色資料，並不會將每項自訂演奏與 FX 設定當成該聲部的獨立配置。效果器處理的是混合後的訊號；各疊層沒有獨立的 FX 鏈。已儲存的 MY STACKS 不保證會在獨立 App 與 AUv3 之間同步。

M2DX-Core：從音符到音訊

M2DX-Core 是 Swift 6 合成函式庫，與 App 及其外掛封裝分開。它實作運算子、32 種演算法、包絡、音高與縮放、發聲配置、音色資料結構，以及合成端的控制器處理。App 則提供連線、MIDI-CI/PE、介面、購買、儲存與效果器。

MIDI / 參數→ 事件佇列 / 快照→ M2DX-Core 發聲單元→ 混音→ App FX→ 音訊輸出

定點運算子與查找表

主要運算子計算使用 Int32 Q24 類型的相位與訊號數值。一個相位週期對應 224 個單位，較寬的 Int64 中間乘積可透過位移回到所需尺度。Q24 是內部數值表示法，不是音訊檔案格式，也不代表整個 App 只使用整數。

Modern 使用具有 1024 個區間的正弦表與線性插值；指數表則將對數電平轉為振幅。查表與插值可避免為每個運算子的每個取樣點計算完整正弦或指數運算。這些表格在初始化時準備，並非由編譯器產生。頻率轉換、控制器正規化、LFO、混音與 App 效果器也會使用浮點運算。

包絡與穩定渲染

運算子包絡使用內部 Q16 表示法，以區塊更新，再由合成核心對增益或衰減進行插值。引擎以最多 64 個取樣點的內部區塊運作。參數快照與事件佇列將變更送入渲染流程；預先配置的儲存空間與原子通訊設計，旨在避免音訊回呼中的等待與記憶體配置。

這個內部區塊大小不代表輸入的 MIDI 事件具有取樣點精度。在已發布的獨立 App 路徑中，來源時間戳記不會用來將音符事件排程到個別取樣偏移位置。AU 路徑會在渲染前處理事件清單，而非依每個事件時間切割緩衝區。實際聽到的時序也取決於宿主、作業系統、緩衝區與連線。

複音與疊層

在關閉超取樣、齊奏為 1、Voice Stack 為 1 的一般單一音色配置下，可用發聲數為 16。疊層／齊奏／堆疊的每個副本都會消耗處理用發聲單元；超取樣會改變可用數量。函式庫較大的內部緩衝區上限，不保證手機能可靠地演奏數千個獨立琴鍵音符。當裝置無法負荷時，請減少倍增數量與效果器。

來源：SynthEngine、DX7Voice、正弦表、包絡。

Modern、Mark I、Depth 與 Vintage DAC

Modern 使用與 MSFA 類型參考模型相關的整數正弦與增益核心。它不是獨立的「Clean Float32」引擎。Mark I 使用參考原始 OPS 行為公開說明的對數正弦／指數模型：將相位折疊至單一象限、合併對數衰減，再轉回振幅。它並非對原始晶片每個操作進行週期精確的模擬。

Mark I Depth 實際改變什麼

Mark I Depth 是前向調變的除數，不是輸出音量、位元深度或包絡速度。÷1 會保留強烈調變；較大的除數會減弱送入下一個運算子相位的訊號，通常使聲音較不明亮。此控制項不會直接將載波輸出或回授訊號除以該值。

在獨立 App 中使用 Settings → Audio → Mark I Depth：範圍為 ÷1–÷16，以 0.1 為步進，可免費調整。目前預設為 Mark I、÷1.0，並關閉 DAC；先前儲存的偏好設定可能覆蓋預設值。Pro 另外提供 Modern/Mark I 選擇與 Vintage DAC 選項。切換引擎會停止目前發聲的音符，因此請在樂句之間變更。

AU 初始值注意事項：宿主參數宣告的 Depth 預設值為 1，但 AU 引擎初始化時設為 5。宿主可能重新套用其參數狀態。尚未針對每個宿主測試首次開啟時的最終值；比對聲音時請明確設定。Engine/Depth 有控制設定函式，但渲染事件自動化處理這些控制項的方式與一般音色參數不同，因此請驗證宿主行為，不要假定每條自動化路徑都可運作。

Vintage DAC 與超取樣

選購的 Vintage 12-bit DAC 會對原始 Mark I 發聲輸出施加與振幅相關的壓擴處理及量化。它是獨立的音色塑造階段，不只是最終輸出的位元破壞效果，也不是 MIDI 解析度設定。獨立 App 的 Audio 也提供 Oversampling OFF/HQ/Low。請以聆聽比較並監控 CPU 負載；超取樣不一定能改善每個音色，而且會改變可用的發聲資源。

參考測試能確認的範圍

Core 包含將 Modern 整數計算與 Apache 授權的 MSFA/Dexed 參考實作進行取樣比較的測試。有些測試注入參考相位增量，以單獨檢驗核心；正式執行時的音高計算是另一條路徑。Mark I 測試則與獨立撰寫的 C 對照實作比較，其中包含與 App 預設 ÷1 不同的 ÷8 測試條件。這些測試不能證明所有最終 App 輸出、Dexed 設定或實體 DX7 錄音都逐位元相同。

認識 MIDI 2.0：訊息與解析度

MIDI 傳送演奏指令，例如要演奏哪個音符、力度多大，以及踏板如何移動。接收端的合成器負責產生音訊。MIDI 2.0 不會改變音訊取樣率或音訊檔案位元深度。

UMP（Universal MIDI Packet） 是可承載 MIDI 1.0 與 MIDI 2.0 訊息的封包格式。連線中出現 UMP，本身並不能證明使用了高解析度 MIDI 2.0 Channel Voice 資料。CoreMIDI 可依接收端 API 與所選協定進行協定轉換。請參閱 Apple 的 CoreMIDI 說明。

較高解析度能做與不能做的事

當傳送端、連線與聲音引擎都保留並使用較精細的控制值時，可以減少階梯感。將鍵盤的 7 位元值轉入 16 位元欄位，不會產生鍵盤從未量測到的額外細節。範圍為 0–99 的 DX7 參數，即使接收到高解析度控制器訊息，仍只有該離散範圍。請參閱 MIDI 位元縮放與解析度。

群組、通道與逐音表情

適用的 UMP 訊息最多有 16 個群組，每組 16 個通道。這些位址不保證 App 具備 256 個樂器聲部或 256 個複音。MIDI 2.0 也定義逐音音高與控制器，可用來只彎音某個按住的音符，而不影響和弦中的其他音符。M2DX 實際的路由限制見下一章。

MIDI 1.0 已具備複音按鍵壓力。傳統 MIDI 1.0 MPE 會將音符分配到不同通道，以取得進一步的逐音控制；原生 MIDI 2.0 逐音訊息則使用不同的表示方式。現代 MPE Profile 也涵蓋 MIDI 2.0，因此「MPE」與「MIDI 2.0」並非互斥標籤。請參閱 MPE 規格及 MIDI-CI MPE Profile。

為何 16 位元力度不代表 65,536 種不同的 DX7 反應

協定數值以 16 位元形式到達 Core，但 DX7 力度靈敏度計算會將其右移縮減為 7 位元，再查詢含有 64 個項目的表格。運算子的靈敏度設定會進一步影響結果。FX 控制項會將數值縮減至 0–127；運算子輸出電平使用 DX 的 0–99 範圍。通道控制項也會經過正規化。接收到較大的整數，不代表每個整數都會產生不同的可聽狀態。

通道、群組與時序限制

獨立 App 的 Settings 提供 Omni 或通道 1–16 作為輸入篩選。篩選後，群組／通道身分不會保留為獨立樂器聲部。通道彎音作用於整個合成器，而非個別 MPE 成員音符。Core 另有逐音 API，但這些 API 的存在無法補足已發布版本傳輸與路由上的缺口。

MIDI 2.0 不會使此版本具有取樣點精度，也不會消除延遲。來源時間戳記與宿主取樣偏移尚未完整用於逐事件排程。請勿根據 64 取樣點的內部處理區塊推定任何時序保證。

MIDI-CI、Profile 與 Property Exchange

MIDI-CI 讓裝置交換功能資訊。Profile 定義特定音樂用途的共同運作方式，並不是預設音色。Property Exchange（PE） 讓實作者提供具名資源，例如裝置資訊、音色清單或控制項說明。支援 PE 的連線不保證每個 DAW 都能自動編輯每個樂器參數。請參閱 MIDI Association 概覽及 Profile 說明。

舊版 MIDI-CI Protocol Negotiation 程序已在 2023 年修訂中棄用。目前的一般說明應區分功能交換與 UMP 協定選擇。M2DX 已出貨的相容行為，不代表實作了目前所有 Profile 或規格選項。請參閱官方 2023 年修訂說明。

連接控制器並使用 MIDI Learn

在獨立 App 的 Settings → MIDI 中，選取 All Sources 或特定 MIDI Input，再選擇 Omni (All) 或 1–16 中的一個通道。Connected MIDI Devices 與 Refresh Devices 可協助確認連線。BLE MIDI 控制器請使用 Bluetooth MIDI。演奏時可查看頁首的活動指示點。

  1. 長按支援的 FX 滑桿約半秒，不要移動它。
  2. 在其 MIDI Learn 選單選取 Learn CC。
  3. 當 LEARN 閃爍時，移動硬體旋鈕或推桿。第一個收到的 CC 會被指派，學習隨即停止。
  4. 再次長按同一滑桿，可取消等待中的學習。使用 Settings → MIDI Learn → Reset All Mappings 可還原對應。

支援的目標包括 MIX／基本 FX 滑桿、部分 Pro 連續控制項、LAYER DETUNE 與聲部 LVL。不能假定 LAYER PAN、所有 FM 編輯器控制項及所有效果器開關／選項都可學習。一個 CC 只有一個學習目標；新的指派會取代它先前的學習目標。延音等原本的標準功能仍可能有反應，因此請避免不小心將這些 CC 改作他用。

使用 Bank Select 與 Program Change 選取音色

MIDI 數值從零開始。顯示音色編號 1–128 的控制器，實際可能傳送 0–127。CUSTOM 卡片上的 B16 PC0 代表音色庫 MSB 16，以及傳送的 Program Change 0，不一定等於控制器畫面顯示的音色編號。

依用途選擇

  • M2DX 的優勢：可立即演奏的行動樂器、螢幕鍵盤、內建創意效果器與選購疊層。限制包括較少的平台／外掛格式、獨立 App 與 AUv3 的功能差異，以及尚不完整的 MIDI 表情路徑。
  • Dexed 的優勢：桌面 DAW 整合、卡匣管理、硬體編輯與替代調律。它需要桌面環境，且所檢視的內部處理較不像一條完整效果器鏈。
  • 以上是根據記錄功能得出的工作流程結論，不是音質排名。本手冊未針對這兩個版本進行受控聆聽測試或相同渲染測試。

Dexed 的編輯流程請參閱官方概覽與 MIDI CC 快顯選單實作。

搬移音色並公平比較

  1. 在 Dexed 將相容的 32 音色 DX7 卡匣匯出為 .syx。將該檔案匯入 M2DX，並選取相同音色。
  2. 使用單一音色模式。停用 M2DX 疊層、Voice Stack 與額外效果器；移除宿主效果器，並將 Dexed 的輸出濾波與增益塑形調整為中性。
  3. 盡可能比對取樣率、調音、移調、引擎模式、回授、運算子數值、包絡、琴鍵同步與輸入力度。
  4. 另行檢查 M2DX 的 Mark I 除數、EG 模式與 DAC 設定。它們的預設值與縮放方式不一定與 Dexed 同名引擎相同。
  5. 傳送相同的音符序列、音符長度、力度、延音與控制器數值。先比較單音，再比較可能觸發發聲搶占的密集和弦。
  6. 將感知輸出音量調整一致，再比較起音、持續階段頻譜與釋放。若有差異，每次隔離一個參數或處理階段來檢查。

共用音色格式與相關的定點合成技術，不保證輸出取樣值完全相同。差異可能來自引擎行為、控制器轉換、包絡模式、增益、效果器或路由。Core 的參考測試涵蓋特定條件，並不認證每個音色、裝置、取樣率或設定都與 Dexed 或實體 DX7 相同。
