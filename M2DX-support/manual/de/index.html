Version, Voraussetzungen und Geltungsbereich

M2DX ist ein FM-Synthesizer mit sechs Operatoren und 32 Algorithmen. Spielen Sie auf seiner Bildschirmtastatur, schließen Sie ein MIDI-Keyboard an oder laden Sie sein AUv3-Instrument in einen kompatiblen Host. M2DX-Core ist die Swift-Bibliothek, die den FM-Klang erzeugt; die App ergänzt Bedienoberfläche, Presets, MIDI-Verbindungen und Effekte.

  • Dieses Handbuch beschreibt die veröffentlichte Version M2DX 1.7.14 (Build 40)mit M2DX-Core 1.25.0 und MIDI2Kit 1.0.19. Spätere Entwicklungsänderungen sind nicht Bestandteil dieser Anleitung.
  • Der aktuelle App-Store-Eintrag nennt als Voraussetzung iPhone, iOS 18 oder neuer. Er führt auch die Kompatibilität mit Apple-Silicon-Macs ab macOS 15 auf, weist aber darauf hin, dass die iPhone-App unter macOS nicht überprüft wurde. Aus dieser Kompatibilitätsangabe lässt sich weder eine native Mac-Version noch eine für das iPad optimierte Version ableiten.
  • Das Handbuch ist in 11 Sprachen verfügbar. Die veröffentlichte App nennt Englisch als Sprache der Bedienoberfläche. Bezeichnungen wie LIVE und SAVE bleiben hier auf Englisch.
  • Die App und das AUv3-Instrument können kostenlos geladen werden. M2DX Pro ist ein optionaler Einmalkauf; den aktuellen Preis finden Sie in der App. Die verfügbaren Pro-Funktionen unterscheiden sich zwischen eigenständiger App und AUv3.

Die folgenden Beschreibungen unterscheiden zwischen einer Fähigkeit des MIDI-Standards, einer Funktion innerhalb der Bibliothek und einer Funktion, die über die veröffentlichte App tatsächlich erreichbar ist. Das sind unterschiedliche Ebenen der Unterstützung.

Den ersten Klang spielen

  1. Öffnen Sie M2DX und wählen Sie LIVE. Stellen Sie die Lautstärke des Geräts oder Audio-Interfaces zunächst moderat ein.
  2. Blenden Sie die Bildschirmtastatur mit ihrer Umschalttaste ein, falls sie ausgeblendet ist, und tippen Sie auf eine Taste. Externe MIDI-Hardware ist optional.
  3. Tippen Sie in LIVE auf ein Preset. Tippen Sie auf den aktuellen Banknamen , um eine andere Bank zu wählen, und anschließend auf einen Klang dieser Bank.
  4. Ändern Sie die Oktave der Tastatur, um ein anderes Register zu erreichen. Die Bildschirmtastatur beginnt mit Anschlagstärke 100; stellen Sie die Kurve unter Settings → Velocity ein oder verwenden Sie ein externes Keyboard, um die Anschlagstärke beim Spielen zu variieren.
  5. Öffnen Sie FX zur Klangformung oder EDIT zum Ändern der Syntheseparameter. Speichern Sie einen bearbeiteten Klang, bevor Sie einen anderen auswählen.

Schließen Sie für ein USB-Keyboard ein kompatibles Interface oder einen Adapter an und prüfen Sie den MIDI-Empfang. Öffnen Sie für ein Bluetooth-MIDI-Keyboard Settings → MIDI → Bluetooth MIDI und stellen Sie dort die Verbindung her. Bluetooth MIDI überträgt Spieldaten; es ist von Bluetooth-Audio getrennt, das beim Abhören eine spürbare Verzögerung verursachen kann.

Wenn kein Ton zu hören ist, testen Sie zuerst ein Werks-Preset auf der Bildschirmtastatur. So lässt sich ein Problem mit dem Audioausgang von einem Verbindungsproblem des Controllers unterscheiden. Siehe Fehlerbehebung.

Bänke, eigene Klänge und Speichern

Eine Bank fasst Klänge zusammen; die Auswahl eines Klangs ersetzt den aktuellen einzelnen FM-Klang. Werksklänge, importierte SysEx-Bänke und Ihre gespeicherten CUSTOM-Klänge bilden getrennte Sammlungen. Über die Bankauswahl in LIVE erreichen Sie alle.

Einen bearbeiteten Klang speichern

  1. Wählen Sie einen Ausgangsklang und öffnen Sie EDIT.
  2. Nehmen Sie Ihre Änderungen vor und tippen Sie auf SAVE.
  3. Geben Sie einen Namen ein und schließen Sie das Speichern ab. Jeder Speichervorgang erstellt einen neuen eigenen Klang, auch wenn bereits ein anderer Klang denselben Namen hat. SAVE überschreibt keine Einträge.
  4. Zum erneuten Aufrufen kehren Sie zu LIVE zurück, tippen auf den aktuellen Banknamen, wählen am Ende der Bankliste CUSTOM und tippen auf den gespeicherten Klang.

Das Speichern entfernt die Anzeige ungespeicherter Änderungen, verschiebt die aktuelle Bank- oder Preset-Auswahl aber nicht automatisch zu CUSTOM. CUSTOM bleibt verborgen, bis mindestens ein Klang gespeichert ist. CUSTOM speichert den Klang, Controller-Routing/EG-Modus, Mono/Poly sowie Portamento ein/aus/Zeit und interne FX. Ein vollständiges Host-Projekt, eine externe AU-Kette, Engine-/Divisor-/DAC-Optionen, MIDI-Learn-Zuweisungen oder ein TX816-Stack werden nicht gespeichert. REVERT kehrt zum Ausgangszustand der Bearbeitung zurück; INIT initialisiert den Klang nach Bestätigung. INIT setzt nicht sämtliche App-Einstellungen zurück.

Einen eigenen Klang löschen

Halten Sie den Klang in der CUSTOM-Bank gedrückt, wählen Sie Deleteund bestätigen Sie. Dadurch wird der gespeicherte Eintrag entfernt; der aktuell geladene Klang kann weiterhin hörbar bleiben. Bewahren Sie benötigte SysEx-Quelldateien für einen späteren Import separat auf.

DX7-SysEx-Klänge importieren

Eine .syx-Datei enthält MIDI-System-Exclusive-Daten. DX7-Klangdaten beschreiben Operatoren, Hüllkurven und gemeinsame Klangeinstellungen; sie enthalten keine Audioaufnahme. Der Importer der veröffentlichten Version akzeptiert eine 4104 Byte große DX7-Sammelbank mit 32 Klängen. Er prüft Header, 7-Bit-Daten und Prüfsumme; einen Einzelklang-Dump akzeptiert er nicht.

  1. Speichern Sie die .syx-Quelldatei an einem Ort, der über die Dateiauswahl zugänglich ist.
  2. Öffnen Sie Settings → Custom SysEx Banks → Import .syx Bank…, wählen Sie die Datei und tippen Sie auf Done.
  3. Kehren Sie zu LIVE → aktueller Bankname zurück, wählen Sie die importierte Bank und anschließend einen Klang.
  4. Bearbeiten Sie den Klang bei Bedarf und erstellen Sie mit SAVE eine separate CUSTOM-Kopie.

Verwenden Sie für den Dateiaustausch mit M2DX eine Bank mit 32 Klängen. Ein Einzelklang-Dump muss zuerst mit einer Klangverwaltung wie Dexed in eine kompatible Bank eingefügt werden. Die Dateiendung .syx belegt keine Kompatibilität: SysEx-Formate anderer Synthesizer und erweiterte Daten der DX-Familie können abweichen. Eine fehlerhafte Datei oder eine nicht unterstützte Nachricht wird durch Umbenennen nicht kompatibel. Entpacken Sie ein Archiv, bevor Sie dessen Bankdatei auswählen. Der Import desselben Dateinamens fügt eine nummerierte Kopie hinzu, statt die vorhandene Bank zu überschreiben. Wischen Sie in Settings über die Zeile einer importierten Bank, um die Kopie der App zu löschen; das Originaldokument in Dateien bleibt erhalten. Die öffentliche Oberfläche bietet keinen Export-Befehl für Klänge oder Bänke.

DX7 SysEx enthält weder M2DX-Effekte, Pro-Layer, Engine-Einstellungen noch den Zustand des Dexed-Plug-ins. Beginnen Sie einen kontrollierten Klangvergleich mit denselben DX7-Klangdaten und deaktivieren Sie zusätzliche Verarbeitung. Siehe Klänge mit Dexed abgleichen.

Wie FM mit sechs Operatoren Klang erzeugt

Ein Operator ist ein Oszillator mit eigenem Pegel und eigener Hüllkurve. Ein Träger gelangt zum Audioausgang; ein Modulator verändert die Phase eines anderen Operators und erzeugt dadurch zusätzliche Frequenzanteile. FM nach DX-Art ist als Phasenmodulation umgesetzt: Die Signale werden nicht einfach miteinander multipliziert.

OP 2
Modulator→OP 1
Träger→Audioausgang

Der Algorithmus legt fest, wie die sechs Operatoren verbunden sind. Manche bilden lange Modulationsketten, andere haben mehrere parallele Träger. Ein anderer Algorithmus kann den Klang stark verändern, selbst wenn alle Operatorwerte gleich bleiben.

  • Erhöhen Sie den Ausgangspegel eines Trägers , um den hörbaren Pegel dieses Zweigs zu ändern.
  • Erhöhen Sie den Ausgangspegel eines Modulators , um die Modulationstiefe zu erhöhen. Meist entstehen dadurch mehr Helligkeit oder ein komplexeres Spektrum.
  • Verwenden Sie ein ganzzahliges Frequenzverhältnis wie 1:1 oder 2:1 als harmonisch verwandten Ausgangspunkt. Nicht ganzzahlige Verhältnisse erzeugen oft glockenartige oder metallische Klänge.
  • Feedback führt ein Operatorsignal in seinen Rückkopplungspfad zurück. Mehr Feedback kann Obertöne oder eine rauere Klangstruktur hinzufügen.

Eine hilfreiche erste Übung: Wählen Sie einen Algorithmus mit einem einfachen Zweig aus zwei Operatoren, senken Sie die anderen Träger ab, stellen Sie beide Operatoren auf ein Verhältnis von 1:1 und erhöhen Sie langsam den Modulatorpegel. Verkürzen Sie dann nur die Hüllkurve des Modulators: Der Klang beginnt hell und wird im Verlauf weicher.

Wählen Sie in EDIT einen Operator und ändern Sie jeweils einen Parameter, während Sie denselben Ton wiederholen. Operatornummern kennzeichnen ihre Position im Algorithmus; ein Operator ist nicht allein aufgrund seiner Nummer immer ein Träger.

OP1–OP6 wählen den zu bearbeitenden Operator; sie sind keine Solo-/Stummschalter.

Operatorhüllkurven, Tonhöhenhüllkurve und LFO

Jeder Operator besitzt vier Hüllkurvengeschwindigkeiten R1–R4 und vier Pegel L1–L4. Bei Note On durchläuft die Hüllkurve ihre ersten drei Zielpegel; die Haltephase verwendet L3. Note Off startet den letzten Übergang zu L4. Die Raten bestimmen die Übergangsgeschwindigkeit, nicht eine Dauer in Millisekunden. Auch der Abstand zwischen den Pegeln beeinflusst die Zeit.

Für einen kurzen E-Piano-Anschlag lassen Sie den Modulator stark beginnen und schnell auf ein niedrigeres L3 fallen, während der Träger langsamer abklingt. Für einen Flächenklang verlangsamen Sie den anfänglichen Anstieg des Trägers und vermeiden einen zu scharfen Modulatorbeginn. Klingt ein Ton nach dem Loslassen weiter, prüfen Sie R4/L4, Sustain und Hall getrennt.

Die Tonhöhenhüllkurve verändert die Tonhöhe des Klangs im Zeitverlauf. Sie verwendet eigene Raten und Pegel und ist keine weitere Amplitudenhüllkurve. Beginnen Sie mit kleinen Tonhöhenänderungen, da starke Einstellungen den Klang dominieren können.

Der gemeinsame LFO erzeugt periodische Tonhöhen- oder Amplitudenbewegungen. Wellenform, Geschwindigkeit, Verzögerung und Tiefe formen diese Bewegung. Tonhöhenmodulation erzeugt Vibrato, Amplitudenmodulation Tremolo; die Empfindlichkeit des Operators bestimmt die Stärke seiner Reaktion. Key sync bestimmt, ob ein Oszillator oder LFO mit einer Note neu startet. Das kann den Anschlag wiederholter Noten und Vergleiche beeinflussen.

Lassen Sie FM Engine, Mark I Depth und den Controller-EG-MODE während der Bearbeitung unverändert. Dieselben gespeicherten DX7-Zahlen können anders reagieren, wenn sich die Modulationsskalierung der Engine oder das Verhalten der Controller-EG-Verschiebung ändert; siehe Engine-Einstellungen.

Ziehen Sie die vier Punkte im Hüllkurvendiagramm, um die zugehörigen Pegel und Raten einzustellen; höhere R-Werte sind schneller. Der mittlere Pegel der Tonhöhenhüllkurve ist 50. Die Zahlen unter dem Diagramm zeigen Werte an und öffnen keine Texteingabefelder. LFO Speed, Delay, PMD und AMD reichen von 0–99, PMS von 0–7. Verfügbar sind TRI, SAW▼, SAW▲, SQR, SIN und S&H.

Anschlagstärke, Controller, Mono und Portamento

Die LIVE-Tastatur sendet eine feste anfängliche Anschlagstärke von 100; die aktuelle Oberfläche besitzt keinen VEL-Regler. Settings → Velocity → Velocity Curve bietet Linear, Soft, Hard und DX7 Keyboard 1-100. Soft hebt mittlere Werte an, Hard senkt sie ab und die DX7-Option begrenzt Werte über 100. Testen Sie anschlagempfindliche Klänge auch mit einem externen Keyboard.

In LIVE verschiebt TRANSPOSE das gesamte Spiel um ±24 Halbtöne; durch Antippen des Werts setzen Sie ihn auf null zurück. Diese Einstellung ist von der Klangtransposition in EDIT getrennt, und beide Verschiebungen addieren sich. EDIT bietet außerdem PB Range (1–12 Halbtöne) und Tuning (±100 Cent). PB Range wird beim Laden eines Klangs auf 2 zurückgesetzt; die Gesamtstimmung bleibt erhalten.

Ausdruckscontroller zuweisen

EDIT → CONTROLLERS enthält WHEEL (CC1), FOOT (CC4), BREATH (CC2) und A.TOUCH (Kanaldruck). Jeder besitzt Pitch-, Amp- und EG-Werte von 0–99. Pitch steuert Vibrato, Amp die Amplitudenmodulation und EG eine Hüllkurvenverschiebung. Dieses Routing ist von der Zuweisung eines physischen Reglers per MIDI Learn getrennt.

  • EG MODE DX7: wirkt auf Operatoren mit aktiviertem AMS. Ein ruhender Controller kann diese Operatoren abschwächen; beim Anheben werden sie bis zu ihrem normalen Pegel geöffnet. Ein EG-Wert von null deaktiviert diese Verschiebung. Prüfen Sie diesen Modus, wenn ein mit Atem gesteuerter Klang vor dem Blasen stumm ist.
  • EG MODE BOOST: erhöht durch Controller-Eingaben die Operatorpegel einschließlich der Modulatoren, sodass sich neben der Lautstärke auch die Helligkeit ändern kann. Er erhält das frühere Verhalten von M2DX.

Einstimmig spielen

Wählen Sie unter Settings → PerformancePoly oder Mono. Portamento und seine Zeit stehen auch in EDIT zur Verfügung. In Mono gleitet Fingered zwischen überlappenden Noten; Full-time gleitet auch zwischen getrennten Noten. Glissando bewegt sich in Halbtonschritten. Mono verwendet eine Stimme des ersten aktivierten Parts; es spielt weder einen Layer aus acht Parts noch Voice Stack als polyphonen Stack.

Speichern Sie den aktuellen CUSTOM-Klang, um Mono/Poly, Portamento ein/aus/Zeit und Controller-Routing/EG-Modus zu erhalten. Die globale Anschlagkurve, Stimmung, PB Range und die separaten Einstellungen Mono Portamento/Glissando werden nicht in diesem Klang gespeichert. Speichern Sie bei einer AUv3-Sitzung auch das Host-Projekt.

Beim Laden von Werksklängen oder importierten Klängen behält die eigenständige App das aktuelle Controller-Routing bei, während AUv3 es auf die DX7-Standardwerte zurücksetzt. Ein CUSTOM-Klang im aktuellen Format stellt sein gespeichertes Routing wieder her. Speichern Sie eine CUSTOM-Kopie, wenn Sie reproduzierbare Einstellungen für Atem- oder andere Controller benötigen.

Die sichtbare Reihenfolge der FX-Bereiche ist kein Diagramm der Verarbeitungsreihenfolge. CUSTOM speichert die internen FX-Einstellungen einschließlich vorhandener Pro-FX-Einstellungen; die externe AU-Effektkette wird separat gespeichert.

In der eigenständigen Pro-Applautet der Weg P73 → EQ → Drive → Chorus → 1176 → DigitalReverb → Stereo → Maximizer. PREAMP bietet P73-Regler für Verstärkung, Ausgang, Hochpass und Klang. Die normalen Hallregler TIME/LEVEL bestimmen weiterhin Zeit und Anteil.

Ändern Sie jeweils nur wenige Parameter. Mehr Drive, Kompressoreingang oder Maximizer-Eingang kann sowohl die empfundene Lautstärke als auch den Klang verändern. AUv3 verwendet auch nach dem Pro-Kauf die Standard-FX-Kette.

TX816-Layer, Voice Stack und Pro

TX816 LAYER kombiniert unterschiedliche Klänge und/oder Unisono-Kopien. Davon getrennt ist der experimentelle Multiplikator Voice Stack in den Settings der eigenständigen App.

  1. Öffnen Sie LAYER und wählen Sie eine PARTS × UNISON-Aufteilung: 8×1, 4×2, 2×4 oder 1×8. OFF kehrt zum Einzelklangbetrieb zurück. Zum Aktivieren von Layern ist Pro erforderlich.
  2. Tippen Sie in LAYER MIXER auf den Klangnamen jedes Parts und wählen Sie einen Klang. Stellen Sie LVL (−24 bis +6 dB), PAN und optional RND für eine neue zufällige Panoramaposition pro Note ein.
  3. Stellen Sie DETUNE (0–12 Cent) und die Verteilung Even oder Random ein. Spielen Sie über eine externe MIDI-Quelle oder den AU-Host; diese Seite besitzt keine Bildschirmtastatur.
  4. Öffnen Sie FX, um den Stack während der Einstellung der gemeinsamen Effekte weiterzuspielen. Die Rückkehr zu LIVE oder EDIT schaltet auf den Einzelklang um.
  5. Verwenden Sie das Speichersymbol, SAVE STACK und einen Namen, um einen neuen Stack zu erstellen. Das Menü … öffnet MANAGE STACKS mit FACTORY DEMOS und MY STACKS. Gespeicherte eigene Stacks können dort gelöscht werden.

Ein Stack enthält die DX7-Klangdaten seiner Bestandteile, Aufteilung, Verstimmung, Part-Pegel/Panorama und gemeinsame interne FX. Wird ein CUSTOM-Klang für einen Part gewählt, verwendet dieser dessen DX7-Klangdaten, nicht sämtliche eigenen Spiel- und FX-Einstellungen als unabhängige Part-Konfiguration. Die Effekte verarbeiten das gemeinsame Signal; es gibt keine separate FX-Kette pro Layer. Eine Synchronisierung gespeicherter MY STACKS zwischen eigenständiger App und AUv3 ist nicht garantiert.

Die App stellt Verbindungen, MIDI-CI/PE, Oberfläche, Käufe, Speicherung und Effekte bereit.

Festkommaoperatoren und Nachschlagetabellen

Die wesentlichen Operatorberechnungen verwenden Phasen- und Signalwerte nach dem Schema Int32 Q24. Ein Phasenzyklus entspricht 224 Einheiten; breitere Int64-Zwischenprodukte lassen sich zurück auf die gewünschte Skala verschieben. Q24 ist eine interne Zahlendarstellung, kein Audiodateiformat und kein Beleg dafür, dass die gesamte App ausschließlich mit Ganzzahlen arbeitet.

Modern verwendet eine Sinustabelle mit 1024 Intervallen und linearer Interpolation; eine Exponentialtabelle wandelt logarithmische Pegel in Amplituden um. Tabellennachschlagen und Interpolation vermeiden es, für jedes Operator-Sample einen vollständigen Sinus- oder Exponentialausdruck zu berechnen. Die Tabellen werden bei der Initialisierung vorbereitet und nicht vom Compiler erzeugt. Frequenzumrechnung, Controller-Normalisierung, LFO, Mischung und App-Effekte verwenden auch Gleitkommaoperationen.

Hüllkurven und stabile Audioberechnung

Operatorhüllkurven verwenden intern Q16, werden blockweise aktualisiert und ihre Verstärkung oder Abschwächung wird im Synthesekern interpoliert. Die Engine arbeitet mit internen Abschnitten von bis zu 64 Samples. Parametermomentaufnahmen und eine Ereigniswarteschlange übertragen Änderungen in die Audioberechnung; vorab reservierter Speicher und atomare Kommunikation sollen Wartezeiten und Speicherzuweisungen im Audio-Callback vermeiden.

Diese interne Blockgröße macht eingehende MIDI-Ereignisse nicht samplegenau. Im veröffentlichten Standalone-Pfad werden Quellzeitstempel nicht zur Planung von Notenereignissen an einzelnen Sample-Positionen verwendet. Der AU-Pfad verarbeitet seine Ereignisliste vor der Audioberechnung, statt den Puffer zu jedem Ereigniszeitpunkt aufzuteilen. Das hörbare Timing hängt außerdem von Host, Betriebssystem, Puffer und Verbindung ab.

Stimmen und Layer

Die normale Einzelklangkonfiguration besitzt bei ausgeschaltetem Oversampling, Unisono 1 und Voice Stack 1 ein Budget von 16 Stimmen. Layer-/Unisono-/Stack-Kopien verbrauchen jeweils Berechnungsstimmen; Oversampling verändert das Budget. Die größeren internen Puffergrenzen der Bibliothek garantieren nicht, dass Tausende unabhängige Tastaturnoten auf einem Telefon zuverlässig spielen. Reduzieren Sie Multiplikatoren und Effekte, wenn das Gerät nicht mithält.

Modern, Mark I, Depth und Vintage DAC

Modern verwendet den ganzzahligen Sinus- und Verstärkungskern des MSFA-artigen Referenzmodells. Es handelt sich nicht um eine separate „Clean Float32“-Engine. Mark I verwendet ein logarithmisches Sinus-/Exponentialmodell auf Grundlage öffentlich beschriebener Eigenschaften des ursprünglichen OPS: Die Phase wird in einen Quadranten gefaltet, logarithmische Abschwächungen werden kombiniert und anschließend wieder in Amplitude umgerechnet. Das ist keine taktgenaue Simulation jedes Vorgangs des ursprünglichen Chips.

Was Mark I Depth tatsächlich verändert

Mark I Depth ist ein Divisor für die vorwärts gerichtete Modulation, nicht für Ausgangslautstärke, Bittiefe oder Hüllkurvengeschwindigkeit. ÷1 erhält eine starke Modulation; ein größerer Divisor schwächt das Signal ab, das in die Phase des nächsten Operators eingeht, und macht den Klang meist weniger hell. Trägerausgang und Feedback-Signal werden durch diesen Regler nicht direkt geteilt.

Verwenden Sie in der eigenständigen App Settings → Audio → Mark I Depth: ÷1–÷16 in Schritten von 0.1, kostenlos einstellbar. Der aktuelle Standard ist Mark I mit ÷1.0 und ausgeschaltetem DAC; eine früher gespeicherte Einstellung kann ihn überschreiben. Pro ergänzt die Auswahl Modern/Mark I und Vintage DAC. Ein Engine-Wechsel beendet aktuell klingende Noten; wechseln Sie daher zwischen Phrasen.

Hinweis zum AU-Anfangswert: Der Host-Parameter deklariert Depth 1 als Standard, die Initialisierung der AU-Engine setzt jedoch 5. Der Host kann seinen Parameterzustand erneut anwenden. Der endgültige Wert beim ersten Öffnen wurde nicht für jeden Host getestet; setzen Sie ihn für Klangvergleiche ausdrücklich. Funktionen zum Setzen von Engine/Depth existieren, aber die Render-Ereignisautomation verarbeitet diese Regler anders als normale Klangparameter. Prüfen Sie daher das Verhalten des Hosts, statt jede Automationsroute vorauszusetzen.

Vintage DAC und Oversampling

Der optionale Vintage-12-Bit-DAC wendet amplitudenabhängige Kompandierung und Quantisierung auf die rohen Mark-I-Stimmensignale an. Er ist eine separate Klangformungsstufe, nicht bloß ein Bitcrusher am Gesamtausgang und keine Einstellung der MIDI-Auflösung. Audio in der eigenständigen App bietet außerdem Oversampling OFF/HQ/Low. Vergleichen Sie nach Gehör und beobachten Sie die CPU-Last; Oversampling verbessert nicht automatisch jeden Klang und verändert die verfügbaren Stimmenressourcen.

Was die Referenztests belegen

Core enthält Sample-Vergleiche der ganzzahligen Modern-Berechnungen mit einer Apache-lizenzierten MSFA/Dexed-Referenz. Einige Tests speisen Phaseninkremente der Referenz ein, um den Kern isoliert zu prüfen; die produktive Tonhöhenberechnung ist ein separater Pfad. Mark-I-Tests vergleichen mit einem unabhängig geschriebenen C-Zwilling, darunter unter der Testbedingung ÷8, die vom App-Standard ÷1 abweicht. Diese Tests beweisen keine Bitgleichheit jedes endgültigen App-Ausgangs, jeder Dexed-Einstellung oder Aufnahme eines echten DX7.

Lizenzen: M2DX-Core steht unter Apache-2.0, MIDI2Kit unter MIT, und die M2DX-App besitzt eine eigene proprietäre Lizenz. Die nur für Tests verwendete C-Referenz ist nicht die produktive Swift-Bibliothek. Siehe Core-Lizenz, NOTICE, Mark-I-Kern und Bedingungen der Vergleichstests.

Warum 16-Bit-Anschlagstärke keine 65,536 unterschiedlichen DX7-Reaktionen bedeutet

Der Protokollwert erreicht Core mit 16 Bit, doch die DX7-Berechnung der Anschlagempfindlichkeit verschiebt ihn auf 7 Bit und verwendet ihn als Index einer Tabelle mit 64 Einträgen. Die Empfindlichkeit des Operators bestimmt das Ergebnis zusätzlich. FX-Regler reduzieren Werte auf 0–127; Operatorausgangspegel verwenden den DX-Bereich 0–99. Kanalsteuerungen durchlaufen ebenfalls eine Normalisierung. Eine große Ganzzahl zu empfangen bedeutet nicht, dass jede Ganzzahl einen eigenen hörbaren Zustand erzeugt.

Grenzen bei Kanälen, Gruppen und Timing

Die Standalone-Settings bieten Omni oder die Kanäle 1–16 als Eingangsfilter. Nach der Filterung bleibt die Gruppen-/Kanalidentität nicht als unabhängige Instrument-Parts erhalten. Kanal-Pitch-Bend wirkt auf den gesamten Synthesizer, nicht auf eine separate MPE-Mitgliedsstimme. Core besitzt weitere APIs pro Note; deren Existenz schließt die Lücken der veröffentlichten Transport- und Routing-Pfade nicht.

MIDI 2.0 macht diese Version weder samplegenau noch latenzfrei. Quellzeitstempel und Host-Sample-Offsets werden nicht vollständig zur Planung einzelner Ereignisse genutzt. Aus internen Abschnitten von 64 Samples lassen sich keine Timing-Garantien ableiten.

Auch das Laden eines AU-Programms wird auf die Oberflächen-/Steuerseite verschoben; ein Note On zum selben Zeitpunkt wie PC kann daher noch den vorherigen Klang verwenden. Senden Sie die Programmauswahl vor der ersten musikalischen Note und prüfen Sie dies im Ziel-Host.

Klänge übertragen und fair vergleichen

  1. Exportieren Sie in Dexed eine kompatible DX7-Cartridge mit 32 Klängen als .syx. Importieren Sie die Datei in M2DX und wählen Sie denselben Klang.
  2. Verwenden Sie den Einzelklangmodus. Deaktivieren Sie M2DX-Layer, Voice Stack und zusätzliche Effekte; entfernen Sie Host-Effekte und neutralisieren Sie Dexeds Ausgangsfilterung und Pegelformung.
  3. Gleichen Sie Abtastrate, Stimmung, Transposition, Engine-Modus, Feedback, Operatorwerte, Hüllkurven, Key Sync und Anschlagstärke so weit wie möglich ab.
  4. Prüfen Sie M2DXs Mark-I-Divisor, EG-Modus und DAC-Einstellung getrennt. Ihre Standards und Skalierungen müssen nicht mit Dexeds gleichnamiger Engine übereinstimmen.
  5. Senden Sie dieselbe Notenfolge, Notenlängen, Anschlagstärken sowie Sustain- und Controllerwerte. Vergleichen Sie einzelne Noten vor dichten Akkorden, die eine Stimmenverdrängung auslösen könnten.
  6. Gleichen Sie die empfundene Ausgangslautstärke ab und vergleichen Sie anschließend Anschlag, gehaltenes Spektrum und Ausklang. Bei Abweichungen isolieren Sie jeweils einen Parameter oder eine Verarbeitungsstufe.

Ein gemeinsames Klangformat und verwandte Festkomma-Synthesetechniken garantieren keine identischen Ausgangssamples. Unterschiede können durch Engine-Verhalten, Controller-Umrechnung, Hüllkurvenmodus, Verstärkung, Effekte oder Routing entstehen. Die Referenztests von Core gelten für bestimmte Bedingungen; sie bestätigen nicht für jeden Klang, jedes Gerät, jede Abtastrate oder Einstellung eine Gleichheit mit Dexed oder einem echten DX7.
